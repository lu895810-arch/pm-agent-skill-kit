# 从 0 到 1 定义 AI 产品：工作流手册

## 总览
本手册定义「从想法到产品定义」的七阶段流程。每个阶段给出目标、关键动作、应使用的方法论（见 `references/frameworks.md`）、产出物与完成检查点。最终交付物 = 一份填写好的产品定义画布（`assets/product_definition_canvas.md`）。

执行顺序不必僵化，但每个阶段都应有明确产出后再进入下一阶段。

---

## 阶段 0：机会识别与筛选
- **目标**：从一堆想法中筛出值得做的。
- **动作**：列候选机会；用「用户价值 × 可行性 × 差异化」初筛；优先「技术驱动且人有真实痛点」的机会。
- **方法论**：SWOT（初步）、差异化定位。
- **产出**：1–2 句机会描述 + 入选理由。
- **检查点**：能说清「为什么是现在、为什么是我们」。

## 阶段 1：用户与问题定义
- **目标**：锁定目标用户与真实问题。
- **动作**：写 JTBD 句式；找「非消费」替代方案；区分功能/情感/社会 job。
- **方法论**：JTBD。
- **产出**：目标用户画像 + JTBD 陈述 + 当前凑合方案。
- **检查点**：问题有可验证证据（访谈/数据），非拍脑袋。

## 阶段 2：价值主张
- **目标**：明确产品如何缓解痛点、创造收益。
- **动作**：填价值主张画布；对齐三对；用 Kano 区分基本/期望/兴奋需求。
- **方法论**：价值主张画布、Kano。
- **产出**：一句话价值主张 + 痛点/收益映射。
- **检查点**：价值主张针对「用户进步」而非「用了 AI」。

## 阶段 3：差异化定位与竞品
- **目标**：在用户心智中占清晰位置。
- **动作**：做竞品分析维度表；写定位声明；识别护城河。
- **方法论**：竞品分析框架、差异化定位、SWOT。
- **产出**：竞品对比表 + 定位声明。
- **检查点**：能一句话说明「我们和 X 的根本不同」。

## 阶段 4：市场机会评估
- **目标**：判断市场规模与可达性。
- **动作**：估算 TAM/SAM/SOM，给依据。
- **方法论**：TAM/SAM/SOM。
- **产出**：三层市场量级 + 关键假设。
- **检查点**：规模基于「具体 workflow」而非泛化 AI 市场。

## 阶段 5：方案设计与 MVP 边界
- **目标**：定义做什么、不做什么、怎么用 AI。
- **动作**：选人机协作模式(Copilot/Agent/全自动)；定技术路径(提示/RAG/微调)；划 MVP 范围（用 Kano 取舍）。
- **方法论**：人机协作模式、技术路径决策、Kano、Agent 设计原则。
- **产出**：方案概述 + MVP 范围（含明确的不做项）+ 技术选型。
- **检查点**：MVP 聚焦单一核心 job；不做项清晰。

## 阶段 6：北极星与漏斗指标
- **目标**：定义如何衡量成功。
- **动作**：定北极星指标；画 AARRR 各阶段主指标；设计 Hook 触发。
- **方法论**：北极星指标、AARRR、Hook。
- **产出**：北极星 + 漏斗指标表 + 激活 Aha 定义。
- **检查点**：指标可驱动、可量化；北极星非「调用次数」。

## 阶段 7：评测与护栏
- **目标**：确保质量可控、风险可防。
- **动作**：设计 eval 维度与 golden set；定护栏策略；定上线门槛。
- **方法论**：评测体系设计、护栏与幻觉治理。
- **产出**：评测方案 + 护栏清单 + 上线标准。
- **检查点**：有可运行评测集与回归阈值；高风险动作有确认/人审。

## 常见陷阱（AI 产品特有）
1. **技术可行性先于需求**：先有模型能力再找场景，往往伪需求。应先问题后技术。
2. **用 Demo 替代验证**：惊艳 Demo ≠ 可复用价值；需真实用户 + 真实数据 eval。
3. **忽视评测**：无 golden set 就上线，质量不可控。
4. **过度承诺能力边界**：把「可能」说成「必然」，导致信任崩塌。
5. **把「用了大模型」当差异化**：护城河应在数据/场景/工作流/评测。
6. **忽视成本与延迟**：忽略单位经济与体验阈值。
7. **全自动冒进**：错误成本高的环节未保留人在环。
