# 产品框架与方法模型参考

本文件供 skill 在执行「从 0 到 1 定义 AI 产品」时按需检索。每个框架包含：定义、何时用、怎么用、AI 产品注意点。执行中根据当前阶段，用 Grep 在本文件定位对应框架再加载。

---

## 1. JTBD（Jobs To Be Done，待办任务）
- **定义**：用户「雇佣」产品来完成某项进步（job），重点在情境与动因，而非人口统计特征。
- **何时用**：定义目标用户与核心问题、写价值主张、区分「功能」与「用户进步」。
- **怎么用**：
  - 句式：`当用户处于[情境]，想达成[进步]，以便[收益]。`
  - 区分功能性 / 情感性 / 社会性 job。
  - 找「非消费」：用户现在如何凑合解决（替代方案即机会）。
- **AI 注意点**：AI 产品的 job 常是「更快/更便宜地获得专业产出」。警惕把 job 写成「用 AI」，应以用户的**结果**为 job。

## 2. 价值主张画布（Value Proposition Canvas）
- **定义**：把「客户画像」与「价值地图」对齐，确保产品缓解痛点、创造收益。
- **何时用**：Phase 2 价值主张设计。
- **怎么用**：客户侧 = 任务 / 痛点 / 收益；产品侧 = 产品 / 痛点缓解 / 收益创造；对齐三对关系。
- **AI 注意点**：痛点常为「专业门槛高 / 产出不稳定 / 人工成本高」；收益常为「即时、可解释、可控」。

## 3. AARRR 海盗指标
- **定义**：获取(Acquisition) → 激活(Activation) → 留存(Retention) → 营收(Revenue) → 推荐(Referral)。
- **何时用**：设计增长漏斗与指标、定位瓶颈阶段。
- **怎么用**：为每个阶段定义 1 个主指标 + 2–3 个过程指标；找最弱环节优先突破。
- **AI 注意点**：激活常取决于「首次惊艳体验」(Aha moment)——例如首条高质量生成结果；留存与评测质量强相关。

## 4. 北极星指标（North Star Metric）
- **定义**：最能代表「用户持续获得核心价值的单一指标」。
- **何时用**：Phase 6 定方向性指标、对齐团队。
- **怎么用**：找「用户价值 × 可量化 × 可驱动」的交集；配套输入指标 / 输出指标 / 护栏指标。
- **AI 注意点**：避免用「调用次数」作北极星（易被刷量）；优先「成功完成的任务数 / 用户感知价值」。

## 5. Hook 上瘾模型
- **定义**：Trigger → Action → Variable Reward → Investment 的闭环。
- **何时用**：设计习惯性使用、留存与复访。
- **怎么用**：外部/内部触发 → 最简行动 → 多变性奖励 → 用户投入（数据/关注/内容）。
- **AI 注意点**：奖励的「多变性」天然契合生成式 AI（每次结果不同）；需护栏避免信息成瘾或误导。

## 6. Kano 模型
- **定义**：基本型 / 期望型 / 兴奋型需求，决定优先级。
- **何时用**：需求取舍、MVP 范围界定、排优先级。
- **怎么用**：基本（必须有，无则不满）→ 期望（越多越好）→ 兴奋（超出预期，显著提升满意）。
- **AI 注意点**：AI 能力常从「兴奋型」快速沦为「期望型」（用户很快习以为常）；基础稳定性（不胡说）是**基本型**。

## 7. SWOT 分析
- **定义**：优势 / 劣势 / 机会 / 威胁四象限。
- **何时用**：战略盘点、竞品定位、内部能力评估。
- **怎么用**：内部(S/W) + 外部(O/T)；输出策略组合 SO / ST / WO / WT。
- **AI 注意点**：把「模型能力 / 数据壁垒 / 评测体系」纳入优势评估；威胁含合规风险与基础模型快速迭代。

## 8. 竞品分析框架
- **定义**：系统化对比竞品定位、能力边界、商业模式、目标用户。
- **何时用**：差异化定位前（Phase 3）。
- **怎么用**：维度表——目标用户 / 核心 job / 技术路径(RAG·微调·Agent) / 能力边界 / 定价 / 生态。
- **AI 注意点**：重点对比「能力边界」与「评测/质量」，而非功能清单；标注各家的幻觉率与可控性。

## 9. 差异化定位
- **定义**：在用户心智中占据一个清晰、独特、有利的位置。
- **何时用**：Phase 3 形成定位声明。
- **怎么用**：模板——`对于[目标用户]，当[情境]，我们的产品是[品类]中唯一能[差异化价值]的，因为[证据/护城河]。`
- **AI 注意点**：差异化应来自「场景深度 / 数据 / 工作流嵌入 / 评测」，而非「我们也用大模型」。

## 10. TAM / SAM / SOM 市场机会评估
- **定义**：总体市场(TAM) / 可服务市场(SAM) / 可获取市场(SOM)。
- **何时用**：Phase 4 市场机会与规模判断。
- **怎么用**：TAM(全部潜在) → SAM(可服务细分) → SOM(现实可拿下份额)；给出量级与依据。
- **AI 注意点**：AI 市场变化快，用「可服务的具体 workflow」而非「AI 市场总规模」更靠谱。

## 11. AI 专属方法论

### 11.1 模型能力边界评估
- **何时用**：判断「该不该用 AI / 用哪类模型」。
- **怎么用**：列出「能做 / 不能做 / 不稳定」三类；不稳定项需评测 + 护栏。
- **维度**：准确性、可控性、可解释性、延迟、成本、隐私。

### 11.2 人机协作模式设计
- **三档**：
  - (a) **Copilot 辅助**——人主导、AI 建议；
  - (b) **Agent 半自动**——AI 执行、人在关键节点把关；
  - (c) **全自动**——AI 闭环、异常才介入。
- **何时用**：Phase 5 方案设计。
- **怎么用**：按「错误成本 / 可控性」选档；错误成本越高，越靠人。

### 11.3 评测体系设计（Eval）
- **何时用**：Phase 7 与贯穿全程。
- **维度**：正确性 / 相关性 / 安全性(有害·偏见) / 格式合规 / 延迟 / 成本 / 幻觉率。
- **怎么做**：构建 golden set（标注样本）+ 自动指标(BLEU/ROUGE/LLM-as-judge) + 人工抽检；设回归阈值。
- **注意**：没有评测集的 AI 产品不应上线。

### 11.4 技术路径决策：提示工程 vs RAG vs 微调 vs 自训
- **提示工程**：快、零成本、适合通用任务与快速验证。
- **RAG**：需私有/时效知识、可控来源、降低幻觉。默认优先选项之一。
- **微调**：需稳定风格/格式/特定分布，且有足量标注数据。
- **自训/定制模型**：仅当数据壁垒与差异化极强、且资源充足。
- **决策原则**：先用提示工程 + RAG 验证需求，再按需微调。

### 11.5 Agent / 工作流设计原则
- **何时用**：产品核心是多步任务自动化。
- **原则**：明确目标与终止条件；工具/权限最小化；每步可观测可回滚；失败有降级；人在环关键决策。

### 11.6 护栏与幻觉治理
- **何时用**：任何面向用户的生成。
- **怎么做**：来源约束(RAG + 引用) / 输出校验(规则·模型判官) / 不确定性表达(「我不确定」) / 敏感操作确认 / 日志审计。
