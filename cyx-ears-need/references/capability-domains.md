# 通用能力域地图（capability-domains）

需求正文按能力域分组，**一个域一个大写字母**。字母在不同行业装不同内容，骨架不变。

---

## 一、十二个通用域

| 域 | 主题 | 本质问题 | 判断"该不该有这个域" |
|---|---|---|---|
| **A** | 输入与结构化 | 外部素材怎么进来、怎么变成系统可用的结构化数据？ | 有"用户带东西来"的环节就要 |
| **B** | 资产与复用 | 哪些对象要被反复引用？一致性怎么锚定？跨范围怎么复用？ | 有"同一对象在多个产出里出现"就要 |
| **C** | 自动化与智能 | 系统替用户做多少？中间态可编辑吗？失败怎么降级手动？ | 有 AI / 规则引擎 / 编排环节就要 |
| **D** | 核心生产 | 核心能力怎么执行？参数与规格是什么？ | **必有**（产品的立身之本） |
| **E** | 编辑与后处理 | 产出物怎么细化调整？局部修改的成本？ | 产出物需要人工精修就要 |
| **F** | 任务与系统 | 长任务怎么排队、可见、重试、取消？ | 有耗时操作就要 |
| **G** | 生态与扩展 | 开放接口？第三方集成？多语言 / 多区域？ | 有平台化意图就要 |
| **H** | 计量与商业化 | 用量怎么算？成本归集给谁？配额还是计费？何时启用？ | 有成本或收费就要（**即使本版不收费也要**） |
| **Q** | 质检与风控 | 质量怎么校验？偏差怎么提示？拦截还是提示？ | 产出质量不稳定就要 |
| **R** | 治理与合规 | 法规义务？数据安全？审计？备份与保护？ | **必有**（B 端、涉个人信息、涉内容必重） |
| **S** | 规模化管线 | 批量生产怎么编排？进度与产能怎么可视？断点怎么续作？ | 有"批量 / 并发 / 多单元并行"就要 |
| **T** | 多用户与协作 | 账号模型？角色权限？分工审阅？多租户隔离？ | 有"多个人一起用"就要 |

**挑选原则**

- 数一遍产品**真正需要**的域，通常 **5–9 个**。
- 域太多 → 颗粒度太细，合并。
- 域太少 → 漏了横切能力。**最常被漏的三个：T（协作）、H（计量）、R（治理）**——它们不产出炫酷功能，但缺了产品不能上线。

## 二、跨行业字母映射

同一套字母，三种行业装的东西：

| 域 | AI 视频制作平台 | B2B SaaS（比如合同管理） | 消费品 / 电商 | 内部系统（比如报销） | 硬件 + 软件 |
|---|---|---|---|---|---|
| A | 剧本/小说导入与结构化解析 | 合同导入、条款抽取 | 商品与素材导入、主图解析 | 票据 / 发票上传与识别 | 设备接入与固件上报 |
| B | 角色主体库、场景道具库、跨集复用 | 模板库、条款库、历史合同复用 | 商品库、品牌资产、跨店复用 | 报销规则库、科目映射 | 设备档案、配件库 |
| C | Agent 模式（规划树自动执行） | AI 审查与风险提示、自动归档 | 智能选品、自动生成详情页 | 自动审核、智能填单 | 自动诊断、OTA 升级策略 |
| D | 文/图/参考生/首尾帧视频生成 | 合同比对、电子签 | 下单、支付、履约 | 审批流引擎 | 采集、控制、计算 |
| E | 局部修改、对口型、超清 | 批注、红线、修订 | 详情页编辑、客服话术 | 报销单调整、附件替换 | 参数调优、标定 |
| F | 任务中心、排队与重试 | 批量任务、异步导出 | 批量上架、批量改价 | 批量审批、批量导出 | 批量采集、批量升级 |
| G | 一键转绘出海、开放 CLI | 开放 API、SSO 集成 | 多店铺 / 多平台对接 | 对接 ERP / OA / 财务 | 开放协议、第三方生态 |
| H | 用量透明、配额、积分计费 | 席位订阅、调用量计费 | 佣金 / GMV / 交易费 | 部门成本归集、预算 | 设备用量 / 流量费 |
| Q | 抽帧对比、一致性提示、口型提示 | 条款冲突检测、合规检查 | 图片合规、禁词检测 | 票据真伪、超标提示 | 数据质量校验、异常告警 |
| R | AI 标识、备案、实名、审计日志 | 数据驻留、等保、审计 | 个人信息保护、广告法 | 内控、留痕、权限 | 产品认证、安全合规 |
| S | 整季生产管线、批量断点续作 | 批量合同处理管线 | 大促批量作业 | 月度批量周期 | 批次生产 / 车队管理 |
| T | 团队、成员、角色、项目空间 | 组织、部门、角色、数据隔离 | 店铺 / 子账号 / 客服组 | 组织架构、审批角色 | 客户 / 站点 / 运维组 |

**用法**：先定行业列，再逐域问"我们这里对应什么"。**问不出内容的域就删掉**，不要为了整齐硬填。

## 三、从域到需求条目（三步）

### 第 1 步 — 定域

选出产品需要的域，给每个域**起一个具体的名字**（不要只写字母）：

| ❌ 泛 | ✅ 具体 |
|---|---|
| A 输入 | A 剧本与叙事 |
| B 资产 | B 资产管理（核心差异） |
| T 协作 | T 团队与协作 |

**名字里带"核心差异"这类标注**，让读者知道哪个域是产品立身之本。

### 第 2 步 — 逐域列条目草图

每个域列 3–8 条需求名，先只有名字，不展开。例：

```
B 资产管理（核心差异）
  B1 角色主体库（多图 ≤7 + 三视图）
  B2 场景/道具/品牌资产库
  B3 跨镜头/跨集/跨项目复用
  B4 风格统一/风格墙（P1）
  B5 3D 导演台（P2）
```

### 第 3 步 — 标优先级与来源

在草图上标 `P0/P1/P2`，并标出哪些需要拆分。**这一步就要定下来，不要留到写正文时才想。**

**检验草图是否完整的三个问题**：

1. 每个痛点（1.1 节）都能落到至少一条需求上吗？
2. 每条画像诉求（2.2 节）都能落到至少一条需求上吗？
3. 核心差异（1.3 节）落在哪个域、哪几条上？

**答不上来 → 草图不完整，回去补。**

## 四、横切能力检查（写完全部域后过一遍）

这几类需求不属于任何单一域，但必须存在。逐项问"我们有没有"：

| 横切项 | 检查问题 | 典型归属域 |
|---|---|---|
| 账号与身份 | 谁在用？怎么进来？组织怎么建？ | T |
| 权限与隔离 | 谁能看/改什么？数据怎么隔离？ | T + R |
| 用量与成本 | 谁在消耗？消耗归集给谁？超了怎么办？ | H |
| 通知与触达 | 什么事情要通知谁？走什么通道？ | F + T |
| 任务可见性 | 长任务在哪看？失败了怎么知道？ | F |
| 数据生命周期 | 结果存多久？删了怎么恢复？备份多久？ | R |
| 审计与留痕 | 关键操作有没有记录？谁能查？ | T + R |
| 合规义务 | 有哪些法定义务？在哪一步拦截？ | R |
| 帮助与支持 | 用户卡住了找谁？ | F |
| 新手引导 | 第一次用的人怎么上手？ | F |
| 引用与追溯 | 产出能不能回溯到输入与参数？ | F + D |
| 降级与兜底 | 外部依赖挂了怎么办？ | 对应域 + R |

**最常被漏的四个**：用量与成本、审计与留痕、数据生命周期、降级与兜底。

## 五、域过多时的合并原则

| 情形 | 处理 |
|---|---|
| 两个域的需求加起来 < 4 条 | 合并成一个域 |
| 一个域只有 1 条需求，且是保障类 | 并入最相关的域，或在对应章节（非功能 / 治理）里写，不单独设域 |
| 某域全部是 P2 | 该域只留一个域名 + 一行说明，不展开 |
| 两个域共享同一批需求 | 说明边界没划清，重新定义二者差异 |

**目标**：正文里每个域都有实质内容，没有"凑数的空壳域"。
