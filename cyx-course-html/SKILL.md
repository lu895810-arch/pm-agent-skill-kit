# 课堂课件 HTML 制作（cyx-course-html）

把任意课程的素材——课件截图阅读笔记、教案、课程大纲、既有课件 HTML 或用户口述——做成一份**单文件、无依赖、中文、响应式**的课堂版课件（可双轨：全时长版 + 快线）。受众默认中小学生项目课：内容完整、有趣、有深度。

**统一制作的铁律**：所有课件用同一套设计系统——本技能目录下的 `assets/template.html`（完整 CSS + 骨架 + 组件示范页），**CSS 一字不改，只换内容**。禁止另起炉灶、改色板、造新组件；确需新组件，做完后把它沉淀回 `template.html` 的示范页。

> 本技能按 WorkBuddy 环境改造过：静态检查用内置 Grep 工具（不依赖 shell 的 grep），渲染抽查走 `agent-browser` 技能，交付用 `present_files` 打开实时预览。

## 第 0 步：收集素材

按优先级找，常组合使用：

1. **既有课件 HTML**（同系列最完整的一份）→ 结构、口径、风格参考
2. **课件截图阅读整理笔记 / 教案 / 课程大纲**（`*.md`）→ 内容主体
3. **用户口述** → 缺的部分靠第 1 步访谈补齐

项目里没有任何既有课件时，直接把 `assets/template.html` 复制到目标路径起步（制作正式课件时删掉末尾的 DEMO 示范 PART）。

路径约定：源素材与输出文件都用**绝对路径**；Windows 桌面类目录（`C:\Users\...\Desktop\...`）在工具调用里写正斜杠或双反斜杠均可，但不要用 shell 拼接。

## 第 1 步：访谈（AskUserQuestion，推荐项放选项第一位）

必问（通用）：

0. **编排模式**（先问这一条，它决定全篇骨架）：
   - **时长轨制** —— 锁总时长，全时长版 + 快线双轨。用于单次课、工作坊一类有明确边界的课。
   - **章节制** —— 不锁时长，按章节推进，每章以一件产物收尾。用于项目制课程、跨周推进的创作课；每章投入多久由老师自定。
   两种模式的骨架、页头、横幅写法不同，见第 3 步。**用户明确要「不要时间、按章节来」时，就是这一条选章节制。**
1. 课程主题与受众年级
2. 总时长与轨制（仅时长轨制模式；章节制跳过此项，改为确认「分几章、每章的产物分别是什么」）
3. 内容取舍（推荐：知识骨架全保留 + 原版精选趣味环节）
4. 最终成果（课堂交付物：一条视频 / 一份作品 / 一场发布会……）
5. 文件去向（推荐：新建「<课程名><时长>分钟课堂版.html」，旧版不动）
6. 课内完成 or 依赖课前作业（推荐：课内完成）
7. 游戏化叙事（职级晋升 / 闯关集章……）与分组设备（推荐：4–6 人共用设备 + 岗位轮换）

必问（AI 类课程）：**工具链口径**——用哪些 AI 工具、各管什么、边界在哪。已确认口径示例：豆包（对话/初稿/迭代）＋ 即梦（图片）＋ LibTV（**仅约 10 秒单镜头**，不直接出成片）＋ 剪映（总装/字幕/导出）。换课程、换工具时，先让用户确认口径再写。

**用户明确批准设计后才开始写文件。**

## 第 2 步：时间预算 / 章节产物

**时长轨制模式（时间必须算术闭合）**

- 每个 PART 定分钟数：全时长版合计 = 总时长（含休息）；快线 = 跳过 ⚡ 页后的合计 = 快线时长。双轨时间表页两列各自求和，写在正文前部。
- 每页右上角 pace 徽章：`⏱ 核心`（两版都上）/ `⚡ 选做`（仅长版，快线跳过）/ `📎 skip`（附录）。
- 快线跳过的页**不卡**游戏化晋升（写进规则）。

**章节制模式（不锁时长）**

- 不做时间预算、不留 pace 徽章、不写双轨时间表、不放 rest-banner。
- 改为**定义每章的产物**：每章必须以一件产物收尾，并且这件产物会被后面的章节接着用（「没有一件是练手」是这个模式的叙事内核，要在序章说透）。
- **两种模式都不要让课程结构被章节切碎**：如果用户给的是一套「章」，就先核对页数归属——一章盖两件事时必须拆，否则「按章推进」是假的（本次实测：`漫画制作` 与 `作品完善` 原本挤在同一章，拆开后五问/连续角色/署名正好各归其位）。
- 页内的微节奏提示（「组内 3 分钟」「60 秒表决」）**可以保留**——那是活动引导，不是课时规划。但**不要**出现「本页 5 分钟」这类把页面与课时绑定的措辞。
- 课时语汇要清干净：`快线`／`双轨`／`分钟版`／`180 分钟`／`PART ·` 一律不许留；`这节课` 在项目制课程里统一改 `这个项目`。改完用 `check_course.py` 的第 7 项自动扫一遍。

**章节三层定义 ＋ 每章定向页（应试型强引导课程的标准件，2026-09-17 定稿）**

用户要「按概念层／成品层／流程层给每章下定义」，或要「每章开始前有一页指向性小结」时，用这两件，**逐章各一份**（不是逐页）。**形态以本节的「定稿形态」为准**（本节下方第一版曾写成三块式长表，已被用户推翻——那是重复制造机）。

> ⚠️ **命名不要照抄用户原话**（2026-09-17 第三轮被退）：用户最初说「概念层／成品层／流程层」，那是咨询 PPT 的语体。**落地时必须换成人话**，见第 2.6 步「去 AI 腔」——「层」这个字本身就要去掉。定稿的三个名称是：
> `🧠 这一章的道理` ／ `📦 这一章要交的` ／ `🔗 下一章接着用它`，表头 `| 要说的 | 怎么说 |`，
> 块标题 `### 翻开这一章 · 先看三件事（第 0N 章）`。

- **三层定义块**（插在章节横幅之后、该章第一页之前），**压成三行词条**，表头固定 `| 要说的 | 怎么说 |`，**每行不超过一行**：

  ```markdown
  | 要说的 | 怎么说 |
  |---|---|
  | 🧠 **这一章的道理** | 愿望 ＋ 弱点 ＝ 故事发动机，弱点要挡在愿望前面 |
  | 📦 **这一章要交的** | 角色卡（六格）＋ 角色草图 → 学案第 3 页 |
  | 🔗 **下一章接着用它** | 第一件；第 02 章拿它的弱处长麻烦 |
  ```

  **「为什么」的部分（为什么弱点要挡在愿望前面）不留在正文，写进该页说课的「口播」。**
  🔗 第三行信息密度最高：**第几件 / 上接什么 / 下章拿它干什么 / 断了会怎样**。

- **定向页**（标题统一 `### 这一章怎么开工 · 三句话交代清楚`），**瘦成一张两栏卡**，表头固定 `| ✅ 交什么 | 🚫 不许什么 |`，各 3 行：

  ```markdown
  | ✅ 交什么 | 🚫 不许什么 |
  |---|---|
  | **角色卡六格全填满** ＋ 角色草图 → 学案第 3 页 | 不许跳过「先自己想」直接动 AI |
  | 交给**隔壁组复述**：他是谁、会碰上什么 | 不许一字不改抄豆包的原话 |
  | 老师盖章 → 学案第 2 页第 1 格，盖了才换岗 | 不许把弱点写成「有点害羞」这种不挡路的毛病 |
  ```

  左栏三行的语义固定：**交什么（成品＋学案页码）／交给谁（谁复述谁验收）／谁盖章（第几格）**；
  右栏**逐条否定式红线**。收口只留一句
  `> 🧭　全组念一遍，从第 ① 件开工。**顺序别换，跳一步这一章就不算过**`。
  （旧写法「本章定向 · 第 0N 章开工」「跳过一步就不算数」已废弃——「定向」是行政标签，学生看不懂。）

- **三条防重复铁律（这一节的核心，违反就白做）**：
  1. **定向页不放「做什么」步骤表** —— 原「本章 N 件事」页已经有，且带「关联页」页码，比新写的更全。
     两表并存 ＝ 逐字重复。
  2. **定向页不配说课** —— 它的内容该章各内页（角色卡页、豆包页…）已经各自讲过，配了就是新一层重复。
  3. **长段解释进说课，正文只留画面与动作指令** —— 判据：**这段是在讲「为什么」还是在给「做什么」？**
     讲为什么的（P22「写得漂亮反而找不出问题」、P43「顺序本身就在讲怎么改好的」）进说课口播；
     给指令的留正文。**不能动的长句**：提示词正文（指令①②③④⑤ 的内容）、表格口径说明、
     金句收口、页脚——这些瘦了反而看不懂。

- **两条工程铁律**：
  - **这两件都不带 `P NN` 编号**，所以插入它们**不动任何页码、不动任何跨页引用**（比插正文页安全得多）。改完 grep 一次 `^### P \d+` 确认页码序列仍 `== list(range(1, 50))`。
  - **插入顺序**：先在三层块后插定向页，**再**处理章内原有页面；若该章原有的「过关检查」页排在章首，
    定向页要插在它**之前**（定向页紧接三层块，符合「翻开本章先看到干什么」）。插完立刻
    grep `^### (P \d+|本章三层|本章定向)`，核对八组的相对顺序一致（实测第一轮把第 01 章的定向页
    插到了 P09 之后，八章格式不齐，返工一次）。
- **核验脚本化**（这个模式改动量大，别靠肉眼）：数四项——`chars`／页码序列是否连续／
  三层块与定向页各 8／**旧表头残留数必须为 0**（`这一章要立的`、`按顺序做完这`、`做完交什么`）。
  再扫一遍「>55 字的非表格正文行」，逐条判断「为什么 vs 做什么」。

- **跨页逐字重复的扫法**（第二类重复，第一类是同页两块重复）：
  用 Python 统计**出现过 ≥2 次的正文行**，输出 `[Nx] 行内容`。然后按这条判据分流：
  - **同一段话被复制** → 删。典型：每章第 1 页都带一句逐字相同的「学生最容易跳过第一步直接动 AI」，
    有了定向页的「不许跳过…」之后，**首次保留、其余各章改写成该章特有的现场风险**
    （第 02 章＝跳过四个筛子直接投票；第 03 章＝完美主义想回头改；第 04 章＝一听要改就想换角色；
    第 05 章＝先出图再改脚本 / 一格一格分开出图）。改写时顺手补齐该页缺失的「🗣 口播」。
  - **同一个套路被套用** → 留。典型：`✕ 不达标怎么办`、`🎖 盖章两个条件`、`这一章按顺序做这 N 件事`——
    这是**模板一致性**，学生翻到任何一章都认得出这套规矩，删了反而失去可预测性。

## 第 2.5 步：双编号体系（章号.页序 ＋ 连续页码）

章节制课件默认用**两套编号并列**，各有各的用处，不要互相替代：

| 位置 | 写什么 | 例子 | 为什么 |
|---|---|---|---|
| 页标题 | **章号.页序** | `### 1.4　让豆包出 5 个角色候选（第 2 步）` | 老师念「第 1 章第 4 页」，学生一眼知道在第几章的第几页、离本章结束还有多远 |
| 页脚右下角 | **连续页码** | `> 📄 **1.4**　｜　第 10 页 / 共 49 页` | 打印、装订、跳转用；「共 N 页」还能一眼看出整套体量 |

- **章号从 0 起**：序章 = `0`，第 01–07 章 = `1`–`7`，附录 = `8`。页序在**章内**从 1 重新数。
  例：序章 8 页 → `0.1–0.8`；第 01 章 6 页 → `1.1–1.6`；附录 3 页 → `8.1–8.3`。
- **页脚写法固定** `> 📄 **<章号.页序>**　｜　第 <连续页> 页 / 共 <总页> 页`，放在该页最后一个 `---` **之前**，
  前后各留一个空行。它是**页尾**组件，跟 `> ⏱`「✍️」那类行动指令同一层，不要塞进页头。
- **附录/连续页码**：连续页码 = 该页在全文中的出场顺序（1…N），与章号.页序**是两套算法**，别拿一套去推另一套。

**改动必须脚本化**（手改必错，49 页量级肉眼盯不住）。三步走，每步跑完先核验再进下一步：

1. **先建映射表**：`{旧页号: 新编号}` 全部算出来落成文件，人眼核一遍（这一步最便宜，错了改这里）。
   判定章归属要按**字符偏移量**比章标题位置，不能按行号边改边数。
2. **再批量替换**：页标题用 `^### P (\d+)　(.+)$` 换头；**正文里的旧编号引用**统一用 `P\s?(\d{1,2})` 扫掉重写，
   换完立刻 `grep 'P\s?\d{1,2}'`，**残留必须为 0**（否则两套编号打架）。
   正文引用点比想象的多：目录页码范围、各章「本章 N 件事」表的「关联页」列、说课里的跨页指引
   （「那页（P 18）」）、附录 A 的「在哪页」列、跨页提醒——**先扫一遍列清单再动手**，别边改边找。
3. **最后插页码行**：从后往前插（行号才不错位）。插完检查**页标题数与页码行数相等**、
   **逐位配对一致**（第 k 个页标题的编号 == 第 k 个页码行的编号）、连续页码 == `1..N`。
   末尾那一页的页码行放在结尾脚注**之后**。

- **核验脚本一次性查全**：页标题数 / 页码行数 / 两者逐位配对 / 连续页码连续性 / 旧编号残留 = 0 /
  三层块与定向页各 8 / 说课块数 == 页数 / 各章页数分布 / `\n\n\n\n` 连续空行 == 0。

## 第 2.6 步：去 AI 腔（课件交付前的必做一遍）

**触发**：用户说「太 AI 化了」「读着不像人话」「用别的词代替」「从全文视角审视」——**或者你自己交付前主动跑一遍**。
课件的读者是老师和学生，**任何一句读起来像咨询 PPT / 制度文件 / 教科书的话都要换掉**。

### 判据：这句话是谁在说？

| 腔调 | 病灶 | 换成 |
|---|---|---|
| **咨询腔** | 「层」「维度」「颗粒度」「闭环」「链路」「抓手」「赋能」「沉淀」「对齐」 | 说人话：`层` → 直接说是什么事；`闭环` → 有头有尾；`颗粒度` → 细到什么程度 |
| **公文腔** | 「落地」「载体」「该组」「核心目标」「统筹」「把控」「进行」「予以」 | `落地` → 做完 / 做齐；`该组` → 那一组；`核心目标` → 最要紧的那几件事 |
| **教科书腔** | 「本章」「本节」「上述」「此外」「同时」「即」「则为」 | `本章` → 这一章；`此外` → 另外；**面向学生的课件一律用「这一章」** |
| **元描述腔** | 在讲「这份文档是怎么组织的」：「这一章按顺序做这 N 件事，做完交一件成果」 | 直接给指令：「这一章做这 N 件事，做完交出一件东西」 |
| **标语腔** | `**A**　｜　**B**` 双栏口号、`**A** —— **B**` 破折号补语、`不是 X，是 Y` 对照式 | 拆成正常句子：`**A**。B`，或直接把话说完整 |
| **填充腔** | 「首先／其次／最后」三段套、「综上所述」「值得注意的是」「不仅……而且……」对称排比 | 直接陈述；段间必要处用一个承接词（所以 / 相比之下 / 再看） |

> **跨格式语言总纲（2026-09-21 定）**：一切文字产出都要满足**通俗易懂、专业严谨、叙事逻辑闭环、
> 段落衔接流畅、去 AI 味**五条；课件场景另加一条——**读者是老师和学生**，凡需先懂职场 / 行业经验
> 才能读懂的句子，一律换掉。总纲原文见 `~/.workbuddy/MEMORY.md`「语言总纲」。

### 三个批量扫法（脚本化，别肉眼盯）

1. **抽象词扫**：列一张词表（上面四类 + 本项目特有事例），逐词 `count` 并打印所在行，
   一次看清分布再动手。**输出必须带行号和整行内容**，否则看不出语境。
2. **模板句式扫**：找**同一句出现 ≥5 次**的正文行——那是模板占位符，不是内容。
   分流判据同第 2 步：**「同一段话被复制」删/改，「同一个套路被套用」留但可优化措辞**。
   本项目实测：「本章定向 · 第 0N 章开工」8 次、「📦 本章成果：」14 次、
   「顺序别换，跳过一步就不算数」14 次（两个固定模板各 7 次）。
3. **口号行扫**：匹配 `^\*\*[^*]+\*\*(　｜　| —— )` 的行，逐条读一遍。
   **判据：这句是人会说的话，还是文案腔？** 人会说的留（「V1 一个字都不许擦」），
   文案腔的改（「五选一，才叫**你在挑**」→「五个里挑一个，**才轮得到你做主**」）。

### 改法的四条经验

- **尾巴上的补语最容易露馅**：`A，才叫 B` / `A，那才是 C` / `A，这就是 D`——删掉补语或改直陈。
- **破折号别当万能胶**：`A —— B` 里 B 若是 A 的解释，多半是 AI 句式；说话课口播里的破折号
  （语气停顿、口语转折）是正常的，**不要一刀切删破折号**。
- **「不是 X，是 Y」少用**：改成正面陈述（「序章结束不看『听完了没有』，看『填完了没有』」）。
- **改完必抽读**：跑完计数脚本**还要 Read 几段实际内容**。计数只保证「没有那些词」，
  **保证不了「读起来像人话」**——本次就是靠抽读发现 `📦 **这一章交出来的：**角色卡` 缺空格、
  以及一处漏改的 `📦 序章成果：`。

- **每一项内部必须分三层、各占一行**，否则读的人分不清哪句是「要准备的」、哪句是「缺了怎么办」：

  - 行内括号容易被断行劈开（「（P37 有完整清单）」断成 `单）。` 独占一行），用 `<span class="nb">（…）</span>` 包住（`.nb{white-space:nowrap}`）。

- 纸本项必须落到具体页码（「角色卡 P95、四格脚本表 P96」）。**指向的是附录里的空白模板页，不是正文教学页**——正文页含示范答案，印下去学生只能照抄；附录里没有对应空白页就先补一页，再引用它的编号。
- **块内只放「怎么准备」和「缺了怎么办」，不放任何说明性文字**（本块被退回三轮的真正原因）：
  - 标题右侧的副标题（「开课前过一遍 · 缺哪一项都不会让项目停下来…」）**不要写**——那是给读者的旁白，读者看清单本身就知道自己在核对。
  - **块末不加收尾行**（第三轮退回）：曾写过 `📍 六项不必全勾满——断网走投屏演示、积分不够走手绘、没有展板就把四格贴走廊墙。`，看起来是「务实提醒」，实际**把六项预案又说了一遍**——断网、额度不够、没展板这三种情况，每一项的备注里已经各写了一次，块末再总结一次是重复。**网格 `.prep-grid` 关闭后直接收尾 `.prep`**，不要 `.prep-note` 这类收尾元素（CSS 里也不要留悬空规则）。
  - 判据一：这句话是在教老师「出事了怎么办」，还是在解释「这块东西是干什么用的」？后者一律删。
  - 判据二（专治收尾行）：**这条信息在上面某一项里是不是已经说过了？** 说过就不再在块末复述——清单类组件的价值在「逐项可勾」，不在「末尾总结」。

**正文前置组件框的左线对齐（toolnote / prep / page 必须同线）**

正文最前面那几个「框」——使用说明 `.toolnote`、教师课前准备 `.prep`——必须与正文卡片 `.page` 的外框落在**同一条左线**上。错开一个数字，读起来就是「两个体系拼在一起」：外框边缘不齐、内层内容起始线也不齐。

- **不要只用 `max-width + margin:auto` 居中。** `main` 是 `max-width:1280px` ＋ `padding:0 24px`，正文卡片的左线是「居中偏移 ＋ 24」；而只有 `max-width` 的块在视口 **721–1279px 之间会撑满整宽（`left=0`）**，与卡片整整错开 24px。桌面大屏看着正常，一缩窗口就裂开——这个档位最容易漏测。
- 正确写法（外壳自带 24px 内边距时）：

  ```css
  .toolnote{width:calc(100% - 48px);max-width:1232px;margin:24px auto 0;padding:18px 24px;border-radius:16px}
  .prep    {width:calc(100% - 48px);max-width:1232px;margin:14px auto 0;padding:18px 24px 20px;border-radius:16px}
  ```

  `1232 = 1280 − 24×2`，正是正文卡片的宽度；`width:calc(100% - 48px)` 保证窄于 1280 时也留出与 `main` 同样的 24px 边距。
- **窄屏要跟着 `main` 的 padding 走**：`@media(max-width:720px)` 里 `main{padding:0 12px}`，两块也要 `width:calc(100% - 24px)`；同时确认 `.part-banner` 的移动 padding 也是 **12px**（模板里若写 16px，章节标题会比卡片多缩进 4px，同一档次）。
- 同族组件除左线外还要**把规格拉平**，否则仍是两个体系：圆角都 16px、左右内边距都 24px（窄屏 18px）、正文字号都 13.4px、标题 14.5px ＋ `letter-spacing:2px`、两块垂直间距 14px 左右（别一边 `margin-bottom:6px` 一边 `margin-top:16px`）。
- 验收靠**量**不靠看：跑 `assets/align_probe.py <课件.html>`，在 1440 / 1200 / 820 / 600 四档读 `getBoundingClientRect`——`.toolnote`、`.prep`、`.page` 三者的 `left` 与 `right` 必须**完全相等**，内层内容起点（`.toolnote .th` 与第一张 `.prep-item`）也必须相等，四档 `overflow` 全为 0。

- PART 配色节奏：cyan → purple → orange 循环（`.pnum` 与 `.page-num` 同步变色）。
- AI 指令框：`<div class="prompt"><div class="ph">🤖 工具 · 用途 · 指令①</div><div class="pc">…</div></div>`；**指令编号全课连续**（①②③…），同一工具的多步操作用 rankchip（如 剪映①/②/③）。
- 游戏化：P01 放 rank-ladder 等级梯（当前级 `.on`），每个关口页放 rankup 晋升卡（写清条件 + 快线替代授衔路径）。
- 深度点：define-box 黄色变体（`style="border-left-color:var(--yellow);background:rgba(255,231,76,.06)"`）。

**章前通栏引导块 `.chguide`（章节制；紧接每条 `part-banner` 之后，不计页码）**

章节制下，「这一章要干什么、交什么、不许什么」如果散在章内页上，学生翻到第三页才明白整章要交什么。把它抽成一个**不计页码的通栏引导块**，紧接章节横幅，读者一进章就先看到全章的交代，且**页码序列完全不受影响**。

- 结构：`.chguide`（外壳，`max-width:1280px` ＋ `padding:0 24px`，与 `main` 同左线）→ `.chguide-in`（内框，圆角/描边/阴影）→ 两段 `.chguide-h` 小标题 ＋ 各自一张 `.data-table`（两列）→ `.chguide-foot` 收尾一行。
- 内容来自 md 的**两块表**，合成一个通栏：第一段标题写「📖 翻开这一章 · 先看三件事」，表头 `要说的 / 怎么说`，固定三行 **🧠 这一章的道理 ／ 📦 这一章要交的 ／ 🔗 下一章接着用它**（第三行是「产物被下一章接着用」的钩子，章节制的命脉，**不能省**）；第二段标题写「🚩 这一章怎么开工 · 三句话交代清楚」，表头 `✅ 交什么 / 🚫 不许什么`。

**说课弹层 `.lecture`（右下角按钮；用户明确要求时才加）**

默认课件是**纯静态零 JS** 的。但当用户明确要「说课内容不让投影看到、老师点了才弹出来」时，用右下角按钮 ＋ 固定面板实现——**页面正文保持纯画面与指令**，说课不占页、不改页码。

## 第 4 步：内容红线（默认文案，按课程领域微调后经用户确认）

### 4.0 双文件锁步（硬规则）：讲台版 ＋ 备课版 必须同步改、平行交付

本技能产出的是**一对**文件——`·课堂精简版.html`（讲台版，老师投影照讲）与 `·教师导学课件.html`（备课版，老师自读、含 `layout-tag` 版式规格）。两份是同一门课的两种口径，**不是两份独立文档**。

- **任何一处内容改动，两份都要改、且改在同一页同一处**。用户原话：「两个 htm 同步进行修改，产出的文档应该保持一致」。漏改一份 = 两份漂移，属于本技能的硬错误。
- **唯一允许的差别**：备课版比讲台版多 `layout-tag`（版式规格，是 4.1b 明确保留给老师的，讲台版全删）；备课版可承载更多细节。除此之外，示范角色、章节结构、页码、锚点、样稿索引、所有教学内容——两份必须逐字对应。
- **带电位差别的改动也要对齐**：比如删一条 `samplechip`，先确认两份是否都有这条；只有一份有时才只删那份，但要在心里对账「另一份为什么没有」，别顺手漏掉本该同删的。
- 改完跑 `check_course.py` 时**两份都跑**，页数 / 横幅 / 锚点数字必须一致。
- **工具坑（本次实测）**：同一份文件的多个 Edit **不要在一条消息里并行批量发**——并发写互相覆盖，7 条改动只落了 2 条且全部报 success。逐条串行发；批量后必须 grep 复核条数。另外扫描残留时模式要覆盖两位数编号（`A0[0-9]` 漏掉 A10，要用 `A\d\d`）。
- **锁步对可以被用户改指定（2026-09-15 实测）**：本项目用户后来明确「**只修改 `·课堂精简版.html`，同步修改学生作品样稿；别的产出不修改，之后也是**」。也就是说新的锁步对是 **讲台版 ＋ 样稿**，**备课版就此冻结、不再跟改**——两份课件的页数从此允许不一致，别再把「两份数字必须相同」当成硬校验。**收到这种改指定时要先写进项目记忆再动手**，否则下一轮又会顺着旧规则把备课版一起改掉。判据：用户点名了哪几份文件，锁步对就是哪几份；没点名时默认仍是 讲台版 ＋ 备课版。

### 4.1 语域红线：课堂课件的叙述主体是「学生 + 老师」，不是公司

课件是**老师拿去给学生上课**的，不是给职场人做汇报的。整份文件里不许出现公司 / 职场语汇，否则学生读起来是第一层隔膜，老师还得先解释「下班是什么意思」。

**禁用词 → 课堂说法对照（全部实测踩过）**：

| ❌ 职场语汇 | ✅ 课堂说法 |
|---|---|
| 下班时要交的货 / 交期 | 课程结束时要交的货 / 完成时间 |
| 交付物、产物 | 成果、作品（`本章成果`、`序章成果`） |
| 承接方 / 委托方 | 保留（校园场景下「委托书」是设计好的教学情境，不算职场语——但配套的交付/交期要改） |
| 立项 / 结项 | 项目启动 / 收尾 |
| 结营 | 结业 |
| 交接 | 换岗交接 / 收尾 |
| 复盘问题 | 回头看问题 |
| 流水线 | 串起来的一条线 |
| 干到（出品人） | 升到 |
| 岗位轮换 | 保留（是分组角色设计，不是公司岗位） |
| 一节课的作品 | 一件作品（章节制下不锁时长，不写「一节课」） |
| 今天的 / 你们今天做的 | 现在做的 / 这一章的（章节制下整个项目跨多节课，「今天」会暗示一天做完） |

**判据（不确定时问自己）**：这句话如果念给一个初中生听，他需不需要先知道「上班是什么」才能懂？需要 → 换词。

**反向检查命令**（改完跑一遍，应为 0）：
```
Grep pattern="下班|交付|交期|产物|结营|交接|复盘|立项|干到|一节课" path=<课件.html> output_mode=count
```
注意：「课时」允许残留 3 处以内的**否定句**（「不按课时切分」「不分课时」「不锁课时」），那是章节制明确声明自己不锁时长的必要说明；「今天」允许 ≤2 处纯氛围用法（「今天开始，你是一名漫画创作者」这类开场鼓动词）。

**「本课」在章节制下同样要清**（2026-09-15 实测）。它的两个义项都违规：轨制版里它指「这一节课」，章节制版里它指「这一门课」——而项目制课程明明跨很多节课。落在标题里尤其刺眼（「角色卡（本课通用纸本）」→「（成套作品通用纸本）」）。列进了 `check_course.py` 第 7 项的扫描名单，改完自动报数。

**章节制的 `timechip` 文案**：复用 `.timechip` 类但不改 CSS，内容写「📦 本章成果：×× ＋ ××」——**注意写「成果」不写「产物」**，「产物」是职场词，已进扫描名单。序章用「📦 成果：…」（不带「本章」）。

**栏目标签同样在管控范围内**（2026-09-15 实测踩到）：禁用词不只管正文句子，**自造的栏目标签一样算**。实测写「🎁 **最终交付**：每章以一件作品收尾……」——只因为它长得像栏目名，就误以为不受语域约束，结果被 `check_course.py` 第 7 项抓出 `交付×1`。同类高危标签：**最终交付／交付清单／交付物一览／复盘要点／立项说明**。改法：标签写「**要交的东西**」「**最后交出的作品包**」。判据：**任何新写进正文的字符串都要过一遍禁用词表，栏目标签不例外**——改完必须重跑第 6 步体检，别凭「这句读着挺像课堂话」放过。

### 4.1f 系统性说明文案：不要把「课件为什么这么做」写进正文（2026-09-15 新增，用户反馈驱动）

**判据**：这句话是在**教学生**，还是在**解释这份课件本身的设计**？
凡是解释「我为什么这样编排 / 这样设计能带来什么好处 / 接下来我打算怎么安排」的，都是**系统性说明文案**，一律删除。它写给的是审阅者，不是学生——用户原话：「这种系统性说明文案不要」。

**实测踩过的典型句**（用户圈出）：

```
❌ 整个项目的例子统一用同一个人：……所有示范都以他为例——这样学生换页时不会断线，
   老师也不用每页重新介绍背景。

✅ 整个项目用同一个示范角色：初二男生「小满」，校跳绳队替补，想在校运会跳满两百下，
   一被围观就手抖，左手腕缠着一圈旧红绳。第01章到第07章都拿他举例。
```

破折号后面那半句（「这样学生换页时不会断线，老师也不用每页重新介绍背景」）就是**设计意图自述**：它在向读者汇报「我为什么这样设计」，而不是教任何东西。删掉后信息一点没少——学生照样知道示范角色是谁、用在哪些章。

**四类高发句式**：

| 类型 | 例句 | 处理 |
|---|---|---|
| 设计意图自述 | 「……这样学生换页时不会断线」「……方便老师不用每页重讲」 | 整句删，或只留事实陈述前半句 |
| 编排预告 | 「下面每一格都配了例子」「接下来每一章都会……」 | 删——直接给内容，不必预告 |
| 元描述口吻 | 「这一处用豆包**有讲究**」「这里有个讲究」 | 改成直陈：「让豆包只提问，不给答案。」 |
| 自我评价 | 「这一页专门设计了……」「特意安排……」 | 删 |

**保留的边界**（别误删）：**讲手艺的「为什么」要留**。「为什么这么定：角色和麻烦是根基，动了就变成另一个故事」——这是教创作判断，属于正文内容；「看差别：V1 的『拿人家的』是价值观问题」——这是在教怎么读对照表。**区分的尺子**：这条理由对**学生做作品**有用吗？有用 → 留；只对**理解这份课件**有用 → 删。

**`layout-tag` 是例外**：「🖥️ 版式：……」确实是元描述，但它是**备课版专属**的版式规格（老师看设计意图用），讲台版已按 4.1b 全删。别把备课版的 `layout-tag` 当成 4.1f 的违规项一起误删。

**扫查脚本**（写文件避开 PowerShell 管道的编码坑）：

```python
PATS = ["这样学生","这样老师","学生换页","老师也不用","重新介绍背景","换页时",
        "下面每一","上面每一","以下每一","配了例子","有讲究","专门设计","特意",
        "这一页配了","接下来每","为了让学生","方便老师"]
# 命中后逐条人判：是在解释课件设计（删）还是在教手艺（留）
```

**注意**：裸扫「本表」「本页」「这一处」误报率极高——「四格脚本表」是真实交付物的名字，「这一处改动」指的是稿子里的改动。**必须逐条人判**，不要机械替换。

### 4.1b 讲台密度：课件是「照着念的」，不是「读的」（2026-09-15 新增）

同一份内容有两档写法，**先问用户要哪一档再动手**，别自己猜：

| 档位 | 用途 | 字数尺度 | 做法 |
|---|---|---|---|
| **备课版** | 老师自己看，理解设计意图 | 每页 300–360 字 | 卡片带完整解释；`layout-tag` 标注版式；define-box 写「为什么」 |
| **讲台版** | 老师上课照着讲、投影给学生看 | 每页 200–230 字 | 卡片只留**关键词短语**（6–14 字）；删 `layout-tag`；删旁白式解释 |

- **讲台版的改写手法**（实测把 14542 字压到 9288 字，63%）：
  - 卡片正文：整句 → 短语。`豆包会给你一堆候选项。选哪个、改哪里、全是你自己拿主意。它替你想，就不算你想。` → `AI 给参考` / `你做决定`。
  - `check-list` 每条压到 **4–7 字**：`角色卡六格全部填了，没有空着` → `六格全部填了`。
  - `.rankup` 只留「达标条件 ＋ 盖章数 ＋ 进下一章」三件事，删掉所有「为什么这么设计」。
  - **删 `layout-tag`**：它是写给排版者的元描述（「🖥️ 版式：…」），投影出来学生读到只会占心思。
  - `.prompt` 指令框**基本不砍**——那是要学生照抄的，砍了就废了。所以最长的那几页自然都落在指令页（P08/P12/P17/P21/P27），这是对的。
- **保留项**：例子（P07 反差表、P23 V1→V2 对照、P26 删减对照）全留——用户说「中度精简：留关键例子」，例子是这门课的说服力所在。
- **改完必须量一遍**，别凭感觉：把「剥注释 → 剥 style → 按 `class="page"` 切页 → 去标签 → 计字数」写成一个临时脚本，两版对比报出「压缩到百分之多少 + 最长的 12 页」。自检判据：讲台版平均 200–230 字，且除指令页外没有超过 300 字的。
- **两版并存时**：备课版文件名带主旨（`·教师导学课件.html`），讲台版带 `·课堂精简版.html`；不要覆盖原文件（用户明确说「保留现有课件」）。`present_files` 里备课版在前、讲台版在后，或按用户实际使用顺序排。
- 讲台版改完照跑第 6 步体检——**页数、页码序列必须与备课版完全一致**（41 页对 41 页），因为删的是文字不是结构。

### 4.1c 每页必须写清「做什么 / 不做什么」（2026-09-15 新增，用户反馈驱动）

**判据**：学生读完这一页，能不能说出「我现在动手做的第一件事是什么」和「哪种做法我不许做」？
说不出，这页就是**在描述标准，不是在给指令**——用户原话：「根本突出不了动作，让学生做什么？以及不做什么？」

**最容易犯的错：卡片标题写成形容词/名词，正文写成判断句。** 典型的反面例子（真实的 P11 初稿）：

```
① 日常      ② 无人受伤     ③ 一看就懂      ④ 四格装得下
就发生在身边  冲突可以有     不用背景知识    六格才说清就换
```

四张卡读下来全是「什么样的麻烦合格」——是**评价标准**，不是**动作**。学生知道什么是好麻烦，但不知道下一步该干什么、哪种要划掉。

**改法：把并列的标准卡改成「做 / 不做」成对卡。** 同一页 P11 改后：

```
✅ 要选  身边 / 日常，同学一听就点头     ❌ 不选  要讲背景才懂的（科幻/历史/专业事）
✅ 要选  只有他碰得上，别人遇上不是这事   ❌ 不选  谁遇上都一样，换个人照样发生
```

再配一组**带具体例子的对照框**，把抽象筛子落到具体的「留 / 淘汰」清单上：

```
✅ 留下这类：赛前发现跳绳不见了 / 答应带东西结果忘了 / 想道歉又张不开嘴
❌ 淘汰这类：要靠偷抢骗才占便宜的 / 把人弄伤弄哭的 / 拿某个群体开玩笑的 / 六格才讲得完的
```

**四条落地手法**：

1. **卡片正文以动词开头**。`人物关系稳定` → `盯住四个锚点，每格按同一套画`；`贴合弱点` → `看他有没有踩上弱点，逼他面对毛病了吗`。名词短语留作卡片标题，正文补动作。
2. **每组规则配一条「别这样」**。`.tier` 里原有的「规则① ② ③」全是正面要求，末尾补一行红框 `别这样`，把最常见的错误做法点名。这是投入产出比最高的一改——用户要的「不做什么」就落在这里。
3. **`.rankup` 盖章块末尾也补一句「别这样」**。它天然是「达标条件」的集合，补一句否定句（`别把豆包给的原话一字不改抄进去`）就把漏洞堵上了。
4. **自检问句写成动作句**。`① 看得懂吗` → `① 拿去给陌生人看，他能复述吗`——同一个问题，但主语的行为明确了。

**量化自检（确定性，别凭感觉）**：临时脚本扫全部页面，统计两件事——

```python
VERB = ["写","画","挑","选","改","填","交","抄","念","问","看","拿","贴","说","做",
        "删","标","记","读","排","组","投","勾","过","试","找","留","算","砍","回","走","用","定","给"]
NEG  = ["不许","不要","不能","禁止","一律","淘汰","别这样","不许动","不选","砍掉","不能省","没看懂"]
# 判据：NEG 计数为 0 的页 = 没交代「不做什么」，逐页补
```

实测基线（41 页讲台版）：动作词均值从 **13 → 19.3**，有「不做什么」的页从 **29/41 → 40/41**。
剩下的 1 页应是纯速查表（附录参考表），不必强凑。

- **顺序**：密度精简（4.1b）先做，动作化（4.1c）后做。反过来会把已删的字又加回去。
- 补「别这样」会把字数顶上去，所以**加完要复量**：讲台版允许涨到 240–270 字/页，超过 300 就要回头砍别的。

### 4.1d 示范角色贯穿全篇 ＋ 代词消歧（2026-09-15 新增，用户反馈驱动）

**判据**：把任意一页单独投影出来，学生能不能说清「**他**是谁」、「**这**指的是哪件事」？
说不清，这页就是**在页与页之间断线**——用户原话：「容易间歇性记忆，不知道说的啥」。

这是**讲台场景特有的缺陷**，备课语境里不容易暴露：老师从头连着读，代词靠上下文就能补；但上课是逐页翻、每页可能被单独投影，前一页的「他」在后一页就成了悬空指称。

**两个病根，一页一页治：**

**病根一：空占位括号。** AI 指令框和空白表格通篇是 `（名字、愿望、弱点）`、`（把雏形写在这里）`「（精简后的那一句动作）」这类**只有说明、没有例子**的括号。学生照着填，根本不知道要填成什么样。

改法——**每个占位都补一个「例：」**：

```
（名字、愿望、弱点）
→（例：跳跳，想在比赛当天跳满两百下，一到人多的地方就紧张到发抖）

（把雏形写在这里）
→（写你自己的雏形。例：一只住在学校储物柜里、比赛前发现跳绳不见了的小企鹅）
```

**病根二：裸代词。** 卡片、表格、define-box 里大量「他」「这」「它」没有先行词。

改法——**每处抽象说明后面跟一个具体实例**：

| 原来 | 改后 |
|---|---|
| 弱点真的给他添麻烦 | 弱点真的会添麻烦（如「一到人多的地方就发抖」） |
| 一格只画一个动作 | 一格只画一个动作——第二格别同时画「翻书包＋问同桌＋看表」 |
| 呼应前面那件事 | 还是「跳绳不见了」这件事 |

**关键做法：确立一个贯穿全项目的示范角色，在第一章声明，之后每页都用他。**

- 声明位置：序章 P01/P02 加一个 `define-box`，写明角色的**名字／身份／愿望／弱点／标志物**五项，并说明「从第01章到第0N章，所有示范都以他为例」（写「整个项目」，别写「本课」）。
- 字段要求：五项必须互相咬合（愿望具体可画、弱点直接挡愿望、标志物能当画面对照锚点）。实测用的组合——「**跳跳**，一只住在学校储物柜里的小企鹅，想在比赛当天跳满两百下，可一到人多的地方就紧张到发抖、连话都说不利索；标志物是带盖的小书包和一直翘着的尾巴」。
- 好处：学生换页不断线；老师不用每页重新介绍背景；也顺带把 4.1c 的动作化落到具体人身上（「跳绳不见了、攥着衣角开口借、借到了却要等」全程可追）。
- 两份文件**都要加**（备课版给学生看的部分同样受益），不是只改讲台版。
- **四锚点写法**：标志物不要只给一个，给四条「一致性锚点」，其中至少一条是**颜色的独占规则**——跳跳这份是「身形比例（圆身子、短腿，站直大约两个头高）／标志物（书包和翘起的尾巴在每格同一位置）／主色（黑白为主，**书包是画面里唯一有颜色的地方**）／气质（眼睛大而圆，站姿偏缩着）」。颜色的独占规则最省事，学生照着填就能一眼看出跑没跑偏。
- **换角色时别做 find-replace**：新角色的每条要重新推导（原「初二男生／瘦高个／短寸头／深蓝色校服／旧红绳／校跳绳队替补」在跳跳身上全部无对应，得换成「圆身子短腿／黑白为主／带盖小书包＋翘尾」，而不是删掉了事）。同理，示范冲突也要整条换掉：把原来编的「校运会开赛前跳绳不见了、借了根旧绳、上场绊倒」换成样稿里真实的那条「比赛前一晚打开储物柜发现跳绳不见了 → 攥着衣角开口借 → 同学答应了却让他等一轮」，④ 的「卡住」比原来明显得多，教学上更立得住。
- **⚠️ 例子必须带例子标记（2026-09-15 第二次用户反馈，血泪教训）**：示范角色只是**讲课的例子**，不是学生的角色。把示范角色的真值抄进正文时，**绝不能和规则句混写在一句里不带标记**——「做到『还认得出是跳跳』才算过」「新解法贴合跳跳的性格」「角色还是跳跳，一个字没换」这种写法，学生读起来会以为**自己的角色就该是跳跳**，误导极强。三条写法铁律：
  1. **规则句用通用写法**（「你的角色」「主角」），要举例时用「例（跳跳）：…」「例：…」隔开，且例子必须是完整分句，不能借破折号、冒号偷偷混进去；
  2. **对照表/清单里出现示范角色真值时，表头或条目要标来源**——「正面写法（√，以跳跳为例）」「提纲（以跳跳为例）」「角色和第01章一致（例：跳跳还是跳跳）」；
  3. **判定法**：把句中的「跳跳」读成「你自己的角色」——如果句子因此变成错误指令（「你的角色必须是跳跳」），这句就没标好，重写。整页成段展示示范角色作品的（如 V1/V2 对照表、三栏真实填法、五问自检），页首加一句「下面是跳跳那一版」即可，逐句不必再标。
  - 实测修复量：两份课件一轮改了 49 处。批量替换用临时脚本逐对断言 `count==1` 再 replace，**先跑一轮、再跑一轮验证（第二轮应全部 0 命中）**，比逐条 Edit 稳（同文件并行 Edit 会互相覆盖）。
- **空白纸本/模板页：首行放示范行（2026-09-15 第三次用户反馈）**。附录里给学生照抄的空白模板（如三栏修改记录通用纸本），如果只在格子里写「写具体到哪一格。例：…」这种说明混例子，学生看不出**填满之后长什么样**。正确做法：填写说明（每栏从左到右写什么）挪进页首导语一句带过，表格**第一行放一条标了「例（跳跳）」的完整真值示范行**，下面保留空行供填写。模板页的示范行可以和正文的真实填法页（如三栏 P25）重复——附录要自成一体，学生单翻这一页也能看懂。

**顺带做的一处增强：表格加「反面写法（×）／正面写法（√）」对照行。** 抽象的四行提纲、四格脚本最容易只给说明不给例，补一张 ×/√ 对照表比加注释管用：

```
① 想要什么  | 他想变强（×）        | 他想在比赛当天跳满两百下（√）
④ 卡点      | 于是他成功了（×）    | 同学答应了，却让他等一轮——他站着等，不敢催（√）
```

**量化自检（确定性）**：临时脚本统计两件事——

```python
# 1) 只有说明、没有「例：」的括号占位
BARE = re.compile(r"（(?![^）]*例[:：])([^）]{2,40})）")
# 判据：命中项若属于「填写类占位」（不含「附录有…」「比如…」这类纯注释），逐处补例
# 2) 疑似悬空代词
PRON = ["他卡", "它替", "本来那样", "这件事办不成", "那个东西"]
```

实测基线（两份 41 页课件）：备课版 16956 字（397 字/页）、讲台版 14036 字（329 字/页）。

**两个坑（都踩过）**：

1. **补例子会把字数顶上去**。讲台版从 268 → 329 字/页。仍在「300–350」可接受档内，但如果原本已到 300，补完要到 350 以上，就得回头砍别处。
2. **补例子时容易带进语域红线**。实测在 P01 补说明时写了「**本课**例子统一用同一个人」——直接触发 4.1 的禁用词。补完**必须重跑第 6 步体检**，别只看标签配平。正确写法：「整个项目的例子」。

### 4.1g 学生作品样稿的接入：整份替换示范角色 ＋ `.samplechip` 索引（2026-09-15 新增，用户反馈驱动）

**触发**：用户丢来一份**往届学生作品样稿**（如《企鹅的跳绳》学生作品样稿.html），说「可以拿这个作品样稿进行举例」。

**先问两句再动手，因为两处选择的工作量差 40 页：**

1. **接入方式**——(a) 加样例索引（轻，只挂指针）／(b) **把示范角色换成样稿主角**（重，全篇替换）／(c) 框架留自创角色、例值填样稿主角。用户本次选 (b)。
2. **抄录深度**——只写索引／关键一两件抄全／全部抄进课件。用户本次选「全抄，但**要没有违和感地融入，不要机械生硬地塞进去**」。

**"不违和" 的具体做法（本次实测有效）：**

1. **先建映射表再改文件**。用临时脚本从样稿里把真值抠出来，列成一张对照表（角色卡六格／四个锚点／四行提纲／V1 脚本／问题清单／三栏修改记录／成品信息／全局替换注意），
   再拿这张表去改两份课件。**跳过这步就会退化成 find-replace**，结果生硬。
2. **每个属性都要"重新推导"，不能平移**。见 4.1d 最后一条：新角色身上没有对应的旧属性就直接重写，别删了事。
3. **冲突要整条换**。示范故事的因果链（愿望→失去→行动→卡住）按样稿重写，别只换人名。
4. **样稿里的真实台词、真实修改记录优先于自己编的**。本次 P36 的 30 秒讲解词样例直接用了样稿原文
   （「…豆包给了五个新解法，我们挑了『开口借』：他攥着衣角问同学能不能借十分钟。结果同学答应了，却让他等一轮——这样才有味道。」），比自己编的示范词强得多。
5. **三栏修改记录要抄全三行**，样稿写了几行就几行（本次从 2 行补到 3 行：改第三格／改第四格／改第二格）。

斜体虚线紫胶囊，跟在 `.timechip` 之后写。挂在**每一处学生要产出东西的页面**，直接写成一句说明——讲清这件产出「长什么样」：

```html

```

挂载位置（两份各 7 处，同一页同一条）：角色卡页／四行提纲页／四格脚本页／问题清单页／V1V2对照页／三栏修改记录页／五问自检页。

**胶囊写法铁律（三条，按用户反馈逐轮收紧，别回退）**：

1. **不写文件导航**。❌「看《企鹅的跳绳》的 A04「跳跳是谁」——六格全填满…」。小节号（A04／C03 这类）是样稿内部的翻页坐标，学生不需要记编号；胶囊直接写成说明句，把「长什么样」讲明白（用户圈掉「A04「跳跳是谁」」后定的）。
2. **不写总览与使用建议**。❌「整套成品长什么样：上一届的完整样例《××》——从××一直拆到××，十件产出一样不少。缺网、缺设备的班里可以直接投影它当范例」。它介绍样稿文件本身的结构与完整性，还附使用场景建议，都属 4.1f 机器说明文案。每条胶囊只对应**一个**产出点。
3. **不写设计自述**。❌「本页示例取自上一届学生作品」。判据：这句话在教学生判「什么算合格」，还是在交代课件怎么编的？后者删。

**样稿内部仍可保留小节号**（`A 0n`／`C 0n` 前缀方便人翻），但**课件正文与胶囊一律不引用这些编号**。

### 4.1e 封面页：P01 用「场景大字 ＋ 通关阶梯 ＋ 三格对照 ＋ 核心句」（2026-09-15 新增）

**触发**：用户看到别的课件有封面页，要求照着补一份。追问一次「补成新的一页，还是替掉现有序章第一页」再动手——这决定要不要全篇改页码。

1. **`.scene` 场景大字块**——`min-height:340px`，六条 `position:absolute` 的阶段标签绕在四周（各自用不同色板变量），中间一列：大 emoji（`font-size:62px` ＋ `drop-shadow`）→ 渐变标题（`background:linear-gradient(90deg,#fff,var(--cyan),var(--nebula),var(--magenta))` ＋ `-webkit-background-clip:text`）→ 一行副题（`color:var(--text-dim)`）→ 六枚 `.formula` 小片串成 `→` 链条。

   ```html
     <span style="position:absolute;top:14%;left:8%;color:var(--cyan);font-size:13px">① 立角色</span>
     ... 共六条 ...
     <div><div style="font-size:62px;filter:drop-shadow(0 0 18px var(--cyan))">✏️</div>
       <div style="font-size:clamp(24px,4.4vw,46px);font-weight:900;letter-spacing:2px;background:linear-gradient(90deg,#fff,var(--cyan),var(--nebula),var(--magenta));-webkit-background-clip:text;background-clip:text;color:transparent">四格漫画故事工厂</div>
       <div style="color:var(--text-dim);font-size:16px;margin-top:8px">开工第一天 · 不比谁画得好，比谁把一件小事讲清楚</div>
       <div style="display:flex;gap:8px;justify-content:center;flex-wrap:wrap;margin-top:22px">... 六枚 .formula ＋ → ...</div></div>

   ```
2. **`.info-title` ＋ `.rank-ladder` 通关阶梯**——六格 `.rank-step`，第一格带 `.on`（金色描边，`rd` 写「你现在在这里」）；后续格子 `rd` 里写「本章成果 ＋ 盖章①」。阶梯要跟课程实际的章数对齐，不是照抄原课件的六格。
3. **`.grid3` 三条定位卡片**——固定三句：`AI 给候选/你做决定`、`画得糙不要紧/故事塌了才要命`、`交稿前问一句/陌生人看懂了吗`。这三句是这门课的「定位三连」，换课只换措辞不换结构。
4. **`.formula` ＋ `CORE SENTENCE`** 核心句收尾：`四格讲的是<b>一件事</b>，不是四张好看的画。`（这里的 `<b>` 会渲染成黄色强调，别滥用。）
5. `page-head` 标题写「开场：欢迎来到 ×××」。

**页码怎么处理（关键，两选一）**：

- **替代式（推荐，本次采用）**：新封面页顶掉原本的序章第一页；原第一页的内容**合并进第二页**（本次把「这门课在做什么」并进新 P02，原 P02「六件东西」顺推成 P03）。这样**总页数不变**，只有序章内部内容重新分配，跨页引用全篇只改序章那几处。两份文件都是 41 → **42** 页（因为合并后原第一页腾出的槽位由封面顶上，另有一页内容拆成两页）。
- **插入式**：新封面页插在最前面，其后全部页码 +1。**代价**：`P0x` 形式的交叉引用（课前准备块、附录 C 纸本表、附录 A 工具点表、正文里的「（P31 有空格子纸）」）全部要改，容易漏。

**重编号必须用脚本，别手改。** 手改 20+ 处极易漏，本次就踩了两个坑：

1. **降序替换会把 `id` 和 `page-num` 换错位**——同一个 `<section>` 的 `id="p21"` 配 `P 21` 看着对，但正文顺序已经乱（P21 跑到 P20 前）。
2. **新页面的 `page-num` 会被连带平移**——新写的 P03 因为此刻 `page-num` 正是 `P 03`，被整体后移脚本推成了 P04，跟原 P03 撞成重复 id。

**稳的做法**：先用降序把 `page-num` 全部平移到位；再用一条正则把**每个 `<section>` 的 `id` 强制等于它自己的 `page-num`**：

```python
pat = re.compile(r'<section class="page" id="p[^"]*"><div class="page-head"><span class="page-num([^"]*)">P (\d+)</span>')
s, n = pat.subn(lambda m: '<section class="page" id="p%s"><div class="page-head"><span class="page-num%s">P %s</span>'
                % (m.group(2), m.group(1), m.group(2)), s)
```

跑完立刻打印 `re.findall(r'<section class="page" id="(p\d+)"', s)` 自检 id 序列，再跑 `check_course.py`。

**收尾核对清单**（改完页码必查）：
- 课前准备块里的纸本页码（角色卡 / 四行提纲 / 四格脚本 / 三栏修改记录 / 格子纸 / 五问自检）
- 附录 A 工具点表的「页码」列（5 行）
- 附录 C 纸本表的「页码」列（7 行）
- 正文里所有 `（P31 有…）` 这类括注
- `序章 P05 有完整说明` 这类指向页

**注意**：万一发现 `p21` 在正文里排在 `p20` 前面，**先确认是不是章边界**——本次就是 P21 属第03章末页、P20 属第04章首页，中间隔着 `part-banner`，顺序本来就对，不是 bug。

### 4.2 警示语/规则句：别把同一动作的两个阶段写成并列

规则句、警示句（`define-box` 里的 🚨 那类）最容易犯的错，是**把有先后的两个动作写成并列**，读者读成「二选一」。

**实测案例（P08 警示语被退回一次）**：

> ❌ 原文：**AI 给的是候选，不是答案。**如果你一个字不改直接用，那这个角色是它想的、不是你创造的——按公约，这不算你的作品。**至少改一处，并说出你为什么选它。**

问题两处：
1. **「改」与「选」并列**，读者会懵：到底要我「选」还是「改」？实际是「选中之后必须改」——**选是前提，改是义务**，有先后，不能并列。
2. **「为什么选它」的宾语错位**：上方三步流程里已经写了「说出你为什么选它」这个动作，警示语再重复一次，且与「公约核查你改了什么」对不上号。

> ✅ 改后：**这五个都只是候选项，挑中谁，谁就得被你改过才算数。**一个字不动就抄进角色卡，这个角色是它想的、不是你创造的——按公约，不算你的作品。**名字、身份、特点里至少改一处，再补上你自己想的愿望和弱点。**

改法：把「选」降为**前置条件**（「挑中谁」），把「改」立为**唯一硬要求**（「就得被你改过才算数」）——矛盾消失。

**判据**：一句话里出现两个并列动词，先查它们**是不是同一个动作的两个阶段**。是阶段关系（选 → 改）就不能并列，要写成「前提 + 义务」的结构。
读一遍问自己：**这是让我做一件事还是两件事？两件事的先后是什么？**

**顺带一条**：警示语的落点要**具体到页面上真有的东西**。上例改后落到 P07 已有的五个格子（名字／身份／特点改一处 ＋ 自己补愿望／弱点），与同页三步流程第 3 步逐字对齐——跨页口径一致，读者不会两处看到两种说法。

### 4.1h 三层命名同一套：教程导航 ↔ 首页链条 ↔ 交付清单（2026-09-15 新增，用户反馈驱动）

带「每章产出若干件成果」的项目制课件，会出现**三层各自表述同一批成果**：

| 层 | 位置 | 职能 |
|---|---|---|
| 导航层 | `topnav` 的章节入口（序章 ＋ 01–07） | 老师/学生跳章 |
| 链条层 | 首页 P01 那排 ①–⑥ 胶囊 ＋ 通关阶梯 | 一眼看懂全流程 |
| 清单层 | 「最后要交出 N 件东西」那张卡片阵 | 学生照着交 |

**铁律：三层必须用同一套名字、同一套序号、同一个分组。** 实测这处最容易崩，因为三层是在不同轮次里分别写出来的，各自语感不同：

- **后果一（序号撞号）**：清单层的 `① 角色卡…⑥ 展板` 是「交的件数」，阶梯层若也用圈号标「盖章①–⑧」就是「盖章序号」。两套圈号差一位，学生对着首页数永远少两个。**解法：圈号只留给「交的 N 件」；盖章一律写「第 N 个章」**（正文本来就用这个说法，对齐即可）。
- **后果二（章名两套）**：导航写 `03 V1失败稿`，章节横幅 `pnum` 写 `CHAPTER · 03 · 第一次尝试`。学生点导航进去，落地页标题不一样。**解法：`pnum` 的章名一律照抄导航**（导航是学生点的那一个，以它为准）；横幅 `h1` 里的叙述性标题不必动，风格由 `h1` 承担。
- **后果三（章数 ≠ 件数）**：8 个入口（序章 ＋ 7 章）交 6 件，必然有合流与不产出。**必须有一条显式的对应说明**，且要回答三个必被问到的问题：序章的产出算不算在这 N 件里？哪两章合交一件？哪一章不新增东西？写法是一句 `define-box`：

  > 🧭 **六件对应哪一步**：序章发的是公约、岗位表和这张清单，六件一件都还没动；第01–05章一步交一件；第06章出厂自检不新增，把 ④ ⑤ 补到出厂标准；第07章漫画展交出第 ⑥ 件。

- **清单层的卡片要挂章号胶囊**。卡片原本只有件号（`① 角色卡`），件号对不上导航的章号。在每张卡底部加一个小胶囊，写「导航里那一章的原名」：

  ```html
  <div class="card-copy"><b>① 角色卡</b><br>填满六格 ＋ 画草图<br><span class="chchip">第01章 · 角色诞生</span></div>
  ```

  `.chchip` 是 cyan 细边 mono 徽章（跟 `.page-num` 同族，只表归属不带语义色）。件数 与 章数 不等时，卡片就写章区间：`第07章 · 漫画展`、或合交的写 `第06–07章 · …`。
- **链条层那排胶囊则直接换成清单层的名字**（`① 角色卡 → ② 冲突提纲 → ③ V1 失败稿 → ④ 修改记录 → ⑤ 四格成稿 → ⑥ 展板`），并与导航逐字一致。**首页场景里的浮动标签反而不带圈号、保留动词**（立角色／找麻烦／写第一版／改一稿／画四格／漫画展）——那是气氛层，不承担编号职责；带圈号就不再是气氛，而会跟清单抢序号。
- **顺手会暴露的连带错**：三层分开写时，「V1 失败稿」这类中间件容易被写成「先画第一版」。**要按该章真正交的东西定调用字**——第03章交的是四格**脚本**（写），第05章才是手绘（画）。同段里出现「画／写」混用就是信号。
- **抄一份对应表再动手**：先把「导航入口 → 章名 → 本章成果 → 清单第几件」列成一张四列表，三层一起核对，再落笔改。改完 `check_course.py` 要两份都跑、数字对齐（见 §4.0 锁步规则）。
- **样稿不参与**：学生作品样稿里**不许出现章节号**（它是学生交的东西，不是课件的一部分）。它在自己的编号体系里保持六区顺序，与清单顺序一致即可。

### 4.1i 一页的「示意」要给满本章成果的份数（2026-09-15 新增，用户反馈驱动）

用户原话：「需要有四个格子的示意，提示词也需要有四个格子的示意，不要只给一个，要清晰且逻辑通顺。规划内容紧扣该章的成果」。

**判据：这一章的成果是几件/几格，页上的示意就得给几件/几格。**给少了学生看不出「填满长什么样」，老师还要口头补。实测病灶：第05章成果是「四格脚本表 ＋ 手绘四格漫画」，但脚本表只给了前两格、豆包指令只出「单格参考图」——学生照着做不出四格。

三类落点一起改，才算「给满」：

1. **脚本表 / 对照表**：行数 = 格数。一页只写「第一格、第二格」是残缺的，四格就写四行（`格 ｜ 任务 ｜ 字太多（反例 ×） ｜ 精简后（正例 √）` 四列够用，别把 `镜头` 也塞进表头把列挤窄——镜头用一条 `tier-row` 讲）。行内容必须与样稿的脚本表**逐格一致**（画面 / 对白 / 镜头），这样两份文件互相对得上。
2. **提示词**：从「单格」升级为「按份数一次出」。实测改法——`请帮我画一张漫画单格参考图` → `请帮我画一张四格漫画的参考图。一共四格，放在同一张图上，四格从头到尾是同一个角色`，下面 `四格内容：` 逐格列 `　第一格：（例：…）`。**要写清为什么一起出**：四格一次出完，前后才是同一个角色、同一套画风（单格出四次，角色会长得不一样）。负面要求照旧整段保留。
3. **版式示意**：光有文字表格，学生仍不知道成稿排出来什么样。用 `fourmap` 组件补一张**四格版式示意图**（见组件速查），每格给 `编号 ｜ 任务·镜头 ｜ 一个动作 ｜ 一句短话`，底部一行落款 ＋ 右下角 AI 标注。放在「排版／动手画」那一页最合适——那页本来就是讲「东西摆在纸的哪里」。

**顺手要扫的连带处**：指令速查表（附录 A）里的用途描述、样稿的五问⑤与创作说明（「4 张单格参考图」→「一张四格参考图」）、`<meta name="description">`，都容易被漏。改完统一 grep「单格」。

### 4.3 安全底线与其它默认文案

- **安全底线默认文案（AI 课通用，一字不改）**：不编造、不偷拍；不使用未授权的肖像与声音，不克隆真人声音；AI 生成的图片和视频必须标注「AI 生成 · 示意图」。**AI 写的是初稿，不是答案。**（非 AI 课程替换为本领域的安全/伦理底线）
- 每处 AI 使用都给**可照抄指令**；图像/视频指令必带「负面要求」（不要真实人脸、校徽、品牌、文字、未核实数字）。
- 文字指令必带防编造约束：「缺了标【缺】/【待采访】，不要自己编」。
- 附录 AI 工具速查表行数 = 全课工具点总数（指令框数 + rankchip 标注点）。

## 第 5 步：分块写入（关键工程模式）

单次大 Write（>30KB）可能失败或截断。**必须分块**：

1. Write 第一块（head + CSS 整块 + nav + toolnote + 首个 PART），文件结尾放：
   ```
   <!--@@NEXT@@-->
   </main>
   </body>
   </html>
   ```
2. 每次 Edit：把「`<!--@@NEXT@@-->` + `</main></body></html>`」**整块**替换为「下一批页面 + 新的同款哨兵结尾」。
3. 末块去掉哨兵，正常闭合。每块 15–25KB 为宜（约 4–8 页）。

先 Copy/Write 出模板再原地 Edit 的路线更稳：第一步把 `assets/template.html` 的内容写到目标文件（或让用户确认后直接复制），随后按上面的哨兵模式逐块替换 DEMO 段落。

> ⚠️ **哨兵替换最常见的伤之一：`page-body` 收尾的 `</div>` 被吃掉。**
> `<section class="page">` 内是 `<div class="page-head">…</div><div class="page-body">…</div>`——
> **两个 div，两个都要关**。收尾必须写成 `</div></section>`；只写 `</section>` 是最隐蔽的一种：
> 页面看着完全正常、文字一个不少、`<section>` 也是配平的，**只有 `<div>` 少一个**，
> 而且体检报的是「行号很小的 page-head div 未闭合，被后面某个 `</section>` 抢断」——
> 报错位置和真实出错位置差了几十行，很容易误判成别的地方写坏了。
> **判据**：体检第 1 项出现「`<div>` 未闭合（被 … 的 `</section>` 抢断）」，且该 `</section>` 前面
> 一行不是 `</div>`，就是这个伤。批量修法：全文把 `</section>` 替换成 `</div></section>`，
> 然后对 `div></div></section>` 这类double-counted 形式做一次回退修正（先 `</div></div></section>` → `</div></section>` 一遍，再补 `</div>`）。

> ⚠️ **哨兵替换最常见的伤之二：多余的 `</div>`。** 整块替换时手工数收尾标签极易多写一个：多出来的那个会把 `page-body` 提前闭合——页面看着还在、文字也没丢，但下半页内容少了 23px 内边距，肉眼几乎看不出来（`grid2` 里塞 4 张卡的地方最容易中招：`</div></div>` 提前把外框关掉了，后两张卡跑到框外）。
> **每替换完一块就跑一次第 6 步的 `assets/check_course.py`**，别等整份写完再查——越晚定位越难。

> ⚠️ **批量替换最常见的伤之三：`re.subn` 把捕获组一起吞掉（2026-09-16 新增）。**
> 用正则整块换一个组件（如把整段 `.prompt` 指令框换成新文案）时，若把组件头部写进了捕获组，
> 替换串里**必须写回 `\g<1>`、`\g<2>`**——只给一段纯内容，正则会连头部和收尾的 `</div></div>` 一起吃掉。
> 实测症状：页面看着还在、文字也齐，**只有 `<div>` 少两个**，体检报「line X 的 `<div>` 未闭合（被 line Y 的 `</section>` 抢断）」，
> 报错行号与真实位置差几十行。**判据**：替换后立刻数一次组件外壳
> （`s.count('<div class="prompt">')`、`s.count('<div class="ph">')`、`s.count('<div class="pc">')` 应两两相等），再跑体检的标签嵌套栈。
> 稳妥写法：**别在替换串里省头部**——把 `<div class="ph">…</div><div class="pc">` 原样抄进新串，或老老实实用 `\g<1>`。

> ⚠️ **批量替换最常见的伤之四：新插入的页占用了同一套页码（2026-09-16 新增）。**
> 给文档插一页正文（如「作品包清单」页）时，若新页直接写成 `01`，紧接着又跑「原有页码整体 +1」的倒序替换，
> `s.count('<span class="page-num">01</span>') == 1` 这条断言就变成 `2`，那一档**默默跳过**——
> 结果是新页与原第 1 页都叫 01，后面 03、04… 却已经 +1 到位，页码序列出现两个 01、缺了 02。
> **判据**：替换脚本里每一条断言都要真报错（本轮 13 条只报 1 条，正是这条）；改完立刻抽一次
> `re.findall(r'<span class="page-num[^"]*">(\d+)</span>', s)`，看它是不是从 01 连续到最后。
> **两种稳妥写法**：① 新页先写一个不会撞的占位号（`99`），全部替换跑完再单独把 `99` 换回 `01`；
> ② 事后按**页标题锚**精修——`<span class="page-num">01</span><span class="page-title">跳跳是谁</span>` 这类串是唯一的，比按号码改安全得多。

> ⚠️ **批量替换最常见的伤之五：`python -c "…"` 的脚本里带了反引号（2026-09-16 新增）。**
> 用 Bash 工具跑 `python -c "…"` 时，脚本串里的 Markdown 反引号（`` `assets/comic/p4.png` `` 这类代码标记）会先被 shell 做**命令替换**：
> 那些词被当命令执行、输出为空，于是**写进文件的内容正好缺了这几处**，而脚本退出码仍是 0、一句报错都没有。
> 本轮实测：一条「追加日志」的命令把五处文件名与两个标签名吃空，回读才发现。
> **判据**：写完立刻回读那一段，看有没有突兀的空档、双空格或断句。
> **稳妥写法**：凡脚本内容里要出现反引号（或 `$`、`!`、反斜杠）的，**一律先用 Write 落一份 `.py` 文件再执行**，`python -c` 只留给不含这些字符的单行命令。

### 6.3 全文审视（脚本查不出的四十一类缺陷 — 交付前必跑一遍）

#### 6.3b 跨页引用专查：每一条指针都要能在落点找到实物

上面第 11 条只是「章归属」这一种。**任何一句「见 P0x / 附录 X / 第0N章 / 有…可印」都是可证伪的断言**，必须逐条落到目标页确认真有那件东西。2026-09-16 又扫出四类：

| # | 缺陷 | 怎么查 | 为什么脚本查不出 |
|---|---|---|---|
| 12 | **括注承诺的实物 / 清单根本不存在** | 把全文 `class="nb"` 括注与 `（…P\d+…）` 抄成一张表，逐条翻到落点看那件东西在不在 | 括注是自然语言，不参与任何结构校验。实测「（P30 有空格子纸可印）」——P30 只有填了示范内容的版式示意，没有可印的空白格；「（附录 C 有清单）」——附录 C 只有可印纸本表，没有物料清单 |
| 13 | **同一件东西被 3 处引用，数值彼此不一致** | 同一件纸本 / 指令在「课前准备块 · 附录表 · 正文」三处各出现一次，逐个比页码 · 章节 · 份数 | 三处各写各的，脚本不跨处比对。实测正文写「四格脚本表第03、04、05章都要用」，附录 C 同一张表却写「第03章、第05章」、共 2 份 |
| 14 | **同一句「最…」同时挂在两件东西上** | 搜 `最让人`、`最先`、`最值钱`、`最硬`，看同一顶帽子是不是戴给了两个对象 | 两处各自都成立，只有并排读才看得出冲突。实测「展板上最让人停下来的」既指 V1 原稿（P19）又指三栏修改记录（P25） |
| 40 | **页码体系自己不自洽：正文顺编，附录（或后半段）沿用旧长版号** | 把全文 `page-num` 与 `id="pNN"` 抽成一列，看是不是**逐页 +1**；出现跳号，先判断是「漏页」还是「旧号残留」 | 每一页的数字单看都合法，脚本不校验相邻差。实测 45 页的课件正文到 P38 结束、附录却从 **P91** 起跳（早期 90 页长版压缩后附录号没跟着走），中间空 52 号；用户一翻到最后一页再翻附录就发现「跳到 91 了」 |
| 41 | **同一条多步流程的「数量词 / 字段」在页内卡片、口播、目录行三处各写一套** | 把同一流程的三处描述抄到一起逐字比：**步骤数**（一处 / 三处）、**字段名**（特点 / 住址）、**动作归属**（改 / 自己补） | 三处各自读得通，脚本不跨处比对。实测 P11 三步卡的**标题**写「改三处」、**副标题与口播**却写「至少改一处」；同章目录行又是第三套「改住址、愿望、弱点」，与卡 2 的「名字 / 身份 / 住址」＋ 卡 3 的「愿望 / 弱点自己想」都对不上 |

**编号跳号的判据（别误判成漏页）**：数一遍 `<section class="page">` 的条数，再看各章横幅到页面的归属——**章数与每章页数都对得上、正文号连续无重号**，就是旧号残留，正文一页不缺，只在附录侧改号。

**改法的几条定式（别搞反）**：

1. **指路型承诺改措辞，印纸型承诺要给真纸**。判据是「学生要不要在这件东西上面写字」：
   - 只是**指路 / 参考**（`（P30 有空格子纸可印）`）→ 改措辞指向真实存在的东西（「（四格怎么分，见 P30）」），不为它造页；
   - 是**学生要填的表**（角色卡、四行提纲、四格脚本表、五问自检）→ 必须给真正的空白纸本，**不能拿含示范答案的教学页充数**。
   2026-09-16 实测：附录 C「可印纸本」7 行里有 5 行的落点是教学页（印出来是照抄跳跳的示范），用户要求配真纸——新增附录 E（P95 序章用纸 ＋ 角色卡 / P96 四行提纲 ＋ 四格脚本表 ＋ 五问自检），页码列全改指空白版，课前准备块与正文括注同步。**根本不用印的行要在列里明写**（「四格格子纸：不用印，A3 自己分格，见 P30」），别含糊成又一个页码。
2. **空白纸本的落点只要在正文，附录 E 就必须再放一份**（2026-09-16 补）。这类表的「落点」有两个含义：**教学页**（含示范行，老师讲课用、不印）与**印出来的那张纸**（学生填、老师印）。只要印出来的那张纸要跳回正文某页去印，就补一页附录。实测：P33「三栏修改记录（通用纸本）」表里已经留了两行空格，附录 C 就把它当纸本写成 `P33`，用户仍要求附录补一份——理由是老师要「**在附录一处拿齐所有空白纸**」，不该为了印一张表往前翻。补完把附录 E ③ 的 `info-title` 写上份数与两个使用章，正文那页只留示范行 ＋ 一句括注指回附录。判据一句话：**示范在正文、空白在附录；正文的示范页不算纸本**。
3. **同一件纸本要在三处同口径**：课前准备块的「按组印」清单、附录的印数清单、正文的括注，页码写法必须一致（`P25 / P33` 这种就三处都写全）；份数要与「用在几章」对得上。补了新页要回头改这四处：附录印数清单的表头「空白版在附录 E（P43 / P44 / P45）」、该行的页码与份数、表下 define-box、课前准备块、正文括注。
4. 「最…」这类评价只给一个对象；两个都想要就换掉一个的词（如 P19 改成「它就是最值钱的那一件」，与附录 C 控点③的「最值钱」同口径），P25 保留「最先停下来」。
5. **章横幅的 `pnum` 必须与顶部导航、两处阶梯同名**。导航 `#ch0` 写「序章」、阶梯写「序章」，横幅就不能写「序 · 项目启动」。2026-09-16 统一成「序章」（其余章仍是 `CHAPTER · 0N · 主题` 的写法，附录用 `APPENDIX · 附录`）。
6. **附录跳号要「顺编附录」，不动正文号**（2026-09-16 新增）。改法：正文到 P38 就把附录接成 P39…P45，`page-num` 与 `id="pNN"` **一起改**（id 通常没有 `href` 指向，改完 grep 一次 `#p9` 确认无人引用）；再把正文里指附录的那几处引用同步换掉——**同号不同写法要分开处理**：指代写 `P95`（无空格）、页码片写 `P 95`（有空格），前者可以 `replace_all` 一次换完，后者连着 `id` 得**逐页顺序改**。改完 grep `P ?9[0-9]` 应为 0 命中。**顺便把「正文页 vs 附录页」的引用分两栏记**：正文页引用（P14/P30/P33 这类）只要落点有实物就一律不动，别顺手重排。
7. **多步流程在三处口径不一时，统一到「能覆盖全部字段、且与其他页闭合」的那一套**（2026-09-16 新增）。判据不是「哪处写得多」，而是**哪套能把上下游的字段分完、一格不漏**。实测角色卡六格＝名字 / 身份 / 住址 / 愿望 / 弱点 / 特点，最终取「改三处 ＝ 名字 · 身份 · 住址（前三格）」「自己补 ＝ 愿望 · 弱点（故事发动机）」「特点（记号）归画草图锚点②标志物」，六格刚好分完；再把卡片副标题、口播、目录行**三处同改**。反过来取「至少改一处」会让六格里的三四格没人认领，也与粉条「一个字不改就抄进角色卡 —— 不算你的作品」的力度打架。

**产物**：每条记「页码 ＋ 现在写的 ＋ 改成什么 ＋ 动哪几份」，然后按 §4.0 锁步规则两份同页同处一起改。

#### 6.3c 范例链专查：下游章节的例子必须能从上游推出来

章节制课件的骨架是一条**产物链**：第 N 章交的那件东西，就是第 N+1 章的输入。**同一条链上的范例必须讲同一个故事**——否则学生拿着上一章的成品，照着下一章的范例对不上，「这里说着，那里说着」。

实例（2026-09-16，42 页课件）：第02章「四行冲突提纲」的范例是「他想跳满两百下 → 跳绳不见了 → 他打算开口借 → 借到了却要等一轮」；第03章的 V1 四格脚本范例却是「……→ 趁同学背过身把绳拿走 → 一个人练熟了」。两条例子不是同一个故事——而第04章的对照表又把「拿走／练熟了」标成 V1、「开口借／等一轮」标成 V2，等于第02章那份范例已经提前把 V2 演完了。

**查法**：先把产物链写成一行（角色卡 → 四行提纲 → V1 脚本＋清单 → V2 提纲 → 四格脚本表 → 成稿 → 展板），再把「同一个示范角色的每一件产物」按章排成一列，**逐件往下推**——从上一件能不能推出下一件？推不出来就是断链。

**改法的方向（关键）：改上游范例，别改下游产物。** 下游的全部内容（V1 脚本、问题清单、修改记录、成稿、展板、附录联动）都长在 V1／V2 上，动它等于重写半个课程；上游只有一章、一格例子，改完链条就闭合。具体到这次：把第02章提纲的第四行从 V2 的卡点（「借到了却要等一轮」）换成 V1 的卡点（「话卡在喉咙里，他张不开嘴」）——V1 的「拿走」立刻成了它的失败展开，第04章再让弱点正面发作、第四行自动长成「借到了却要等一轮」，一路推到成稿。

**顺带自查三条**：

- **上游范例必须先过上游自己的关卡**。第02章关卡写着「④必须是卡住、卡点要压在他的弱点上」——范例第四行原为「借到了却要等一轮」，勉强够；换成「张不开嘴」才对得上角色的弱点。
- **产物的「层级」不要混**。提纲的四行（想要／卡在／怎么办／卡点）和脚本的四格（起头／卡住／出手／结果）不是一回事。对照表若写「提纲」，V1 行就得填提纲级的四行；要填脚本级的「拿走／练熟了」，表头就得写成「V1 稿 ／ V2 稿」（本次的改法）。
- **同一章的产物形态不能跳章**。第02章交提纲（文）、第03章交四格脚本＋清单（文）、第05章才交手绘（画）。所以第03章「你会想／该做的」里写「太难看了，重画一张干净的」就跳了章——本章根本不画，范例也全是文字。改「写得太乱了，重抄一张干净的」；附录 C 控点③「学生要撕纸、要重画」同理改「重抄」。

#### 6.3d 课件 ↔ 样稿对齐专查：示范样稿必须是课件的逐条实例

课程若配了一份**示范样稿**（学生作品全文），这份样稿就是课件的**实例**：课件每讲一条口径，样稿里都要找得到它的落实；样稿里出现的每一样东西，课件也都得声明过。两侧各读各的都自洽，**只有并排读才看得出不是同一套**。

| # | 缺陷 | 怎么查 | 为什么脚本查不出 |
|---|---|---|---|
| 15 | **并列框架两边不同名** | 把课件里所有「N 个 X」的并列框架（四个筛子 / 四条尺子 / 五问 / 五块展板）连名字带顺序抄成一行，再到样稿里找同一处，**逐字**比 | 两边各自的卡片都成立，只是不是同一组。实测课件标题写「四个筛子」、卡面却是两组 ✅/❌ 正反（日常／专属），样稿是另外四个名字（日常／无人受伤／一看就懂／四格装得下）——标题悬空，实例落空 |
| 16 | **样稿缺了课件声明的本章成果** | 把每条 `part-banner` 的 `本章成果` 拆成名词，逐件到样稿里找落点 | 成果声明在横幅里，样稿目录只按「要交的几件」排版，缺哪件不报错。实测第01章横幅写「角色卡 ＋ 角色草图」、第07章写「…＋ 观众反馈记录」，样稿两处都没有 |
| 17 | **同一处数字两边对不上** | 样稿里的「N 处 AI 使用点 / N 个候选 / N 个字」逐条与课件附录表核 | 数字写在自然语言里。实测课件附录 A 列了 **5 处**豆包使用点，样稿的创作说明只数到 **4 处**（漏掉「5 种新解法」） |
| 18 | **同一个专名在另一处走样** | 作品名、组名、落款格式、口号在全课只能有一套写法；附录里的「示例作品名」也要与样稿同指一部 | 实测附录 D 的落款示例写《两百下》、样稿写《企鹅的跳绳》——同一部作品两个名字 |

**改法（方向要选对）**：

1. **默认以课件为准**——样稿是课件的实例，课件怎么说，样稿就怎么落。
2. **课件自己没点名时，用样稿里已经写清楚的那套回填课件。**判据：课件那句是不是「悬空引用」？「四个筛子」只有标题、卡片上没有名字，就是悬空——把样稿那四张卡的名字与顺序搬回课件，两边同时成立；**不要为凑名字去改样稿已经自洽的四张卡**。
3. **补页，不并页**。课件横幅声明的成果在样稿里缺件时，在样稿对应成果段补一页（典型两页：「角色草图：剪影＋三个表情＋随身道具」「巡展反馈：观众说了什么／下一版先改哪里」）。补页后**页码整体顺延**——用正则批量改 `page-num`，**按号码倒序替换**（11→12 先做，02→03 后做），否则会连环撞号；补完顺手更新样稿顶部的「成果」条与各成果横幅的 `pdesc`。
4. **标准源另出了一版课件时，样稿就另出一版作品稿，原样稿一字不动**（2026-09-16 新增）。做法同 §6.3h 改法 9：把 `sample-build/template.html` 复制成 `template_<版本>.html`，配一份 `build_<版本>.py` 引同一批 `assets/comic/*`，只在副本上改，原版与它的模板、`build.py` 都不碰。新版要与**新版课件**逐条对齐，下面四处差异都是从标准源读出来的，别改回执行件口径：
   ① **每件成果的横幅改标章号**——`pnum` 写 `CHAPTER · 0N · <章名>`，`h1` 写 `<①…> <件名>`；章与件各司其职，**不复用同一串字**（旧写法「成果 · 01」把章和件说成一件事）；
   ② **展板五块的顺序**按标准源重排，并同步每块的 `key` / `pair` 高亮（哪两块成对、哪一块最显眼）与跟着它的那句说明；
   ③ 第05章**参考图口径**（逐格单格 vs 一次出四格）连同 toolnote 第三张卡、展签创作说明一起改；
   ④ 五问自检的「一条不过回哪」从「回第几**件**」改成「回第几**章**」——标准源的返工路径是按章走的。
   再顺手补两件标准源有、老样稿没有的：**组名与四个岗位的分工块**（含「组员固定不换组、岗位每章往后挪一格」），以及**「最后交的 N 件」作品包清单页**——用户点名要「最后交的东西」时，这一页就是直接回答，放在封面之后最前。

5. **参考图与脚本表对不上时，重出图，别改文字**（2026-09-16 新增）。判定：把每格的「画面（一个动作）」原文与图并排读，**图里多出来的动作就是缺陷**——实例：第四格脚本写「同学让他等一轮，他站着，不敢催」，图里却是两人各握一头一起甩绳、企鹅还在笑。图是下游、脚本表是上游，但**这里恰要把 §6.3c 那句反过来用**：文字链撑着修改记录、五问自检与四步复述句，动它会把整条链带崩，所以要动的是图。做法：
   - 用**原图做图生图**（`image1` 传那张要改的 `pN.png`、`input_fidelity=high`），提示词写成「保持画风／线条／背景／角色造型完全不变，只把动作改掉」＋**目标画面的完整描述**——只说增量（「把企鹅的手松开」）模型会把旧动作留着；
   - **一次只收敛一档**：第一轮先改动作（绳子归谁、谁在跳），第二轮再修**空间关系**（绳子有没有甩到对方头上、两人之间有没有空出距离）与**表情**（脚本说「不敢催」就不能笑，要睁眼看对方、脸上留汗）。两轮内能收敛，别开第三轮；
   - 图片是**多份产出共用的素材**（`assets/comic/finalN/pN.png` 被样稿与各版本作品稿同时内嵌）——换图后**每一份都要重跑自己的 build**，并逐份确认新图已在文件里（`base64(new_png) in html` 为真），再核 `<div>/<section>` 平衡；
   - 换图前把原图另存到 `.workbuddy/gen/`（不进交付区）留退路；`alt` 文案通常已经是对的（文字侧没动过），复核一遍即可；
   - 交付前**把四格并排渲染一张再读一遍**：格与格之间是不是同一个角色、同一个场景，四格连起来是不是脚本表那四句话。

6. **素材自带生成器水印要去掉，且去掉后必须替换回素材并重跑每一份产物**（2026-09-16 新增）。判别两种「AI 生成」：**图片像素里的**生成器水印（半透明白字压在右下角，形如「AI 生成 / WORKBUDDY.CN」）要去；**页面里叠加的**来源标注（`.fc-r`、`fm-mark`、`bd-tag` 里的「AI 生成 · 示意图」）是课程要求学生必标的，**一个都不能动**——两者位置常常重叠，别顺手一起删。
   - 做法：走 `buddy-image-processing` 技能的 `erase` 操作（先取一次凭据，逐张提交，一次一张），提示词照用户原话写「去掉右下角的水印」，不要扩写。
   - **最容易漏的一步**：脚本把结果写在**工作区根目录**（`processed_image_<task>_1.png`），它不是素材——**必须覆盖回 `assets/comic/finalN/pN.png`，再重跑每一份内嵌这批图的产物的 build**（`build.py` / `build_outline.py` 各跑一次），并逐份确认 `base64(new_png) in html`。本轮真踩：四张图都处理干净了，但没替换、没重建，用户回看产物还是带水印的，被退回一次。
   - 核验三件：① 水印区的灰度均值与**峰值**（白色水印去掉后峰值明显下降）；② 全图逐像素差异应 **< 2%**（只该动那一小块，动了别处就说明模型重绘过了）；③ 放大并排比对＋**渲染产物页**确认。旧图另存 `.workbuddy/gen/pN_带水印备用.png`，处理结果用完归档进 `.workbuddy/gen/`，别留在交付区根目录。

**样稿是脚本生成的怎么办**：改完样稿必须**回写生成模板**——把样稿里的 `data:image/png;base64,…` 逐个换回 `{{PANEL1}}`…，覆盖 `sample-build/template.html`，再重跑 `build.py`，**用逐字节比对确认幂等**（否则下次改样稿会被旧模板覆盖回去）。

**产物**：两侧逐条记「哪个口径 ＋ 课件写的 ＋ 样稿写的 ＋ 以哪边为准」，跑完把课件与样稿的逐字比对清单存一份（同名标题、四格四行、落款格式、复述链），下次改动直接复用。

#### 6.3e 小节内部专查：标准 → 逐条代入 → 备选 → 承接下游

「讲一套标准」的小节（四个筛子、四条尺子、五问）毛病几乎都出在**板块的先后与去重**上。实例（2026-09-16，第02章 P12「四个筛子」）：

| # | 缺陷 | 怎么查 | 为什么脚本查不出 |
|---|---|---|---|
| 19 | **同一件事在一个小节里说了三遍** | 把该小节每个板块的「实际信息」抄成一列，看哪几行是同一件事 | 三处措辞都通顺、各自成立，只有并排读才发现重复。实测 P12 ＝ 四张筛子卡（✅/❌）＋「留下这类／淘汰这类」双盒 ＋ `📎` 样例条，三块都在讲「什么样的麻烦过关」 |
| 20 | **标准与实例不对位** | 数标准有几条，再数实例清单有几条，能不能一一对上 | 实例是自由列表，不与标准编号绑定。实测「淘汰这类」4 条只对应筛子②④（筛子①③没有淘汰例），而卡②④的 ❌ 行又把这 4 条重复了一遍 |
| 21 | **盖章检查表盖不全本章的标准** | 把本章横幅的「本章成果」＋小节里的「N 条标准」逐条去 `check-list` 里找落点 | 检查表是手写清单，不与标准联动。实测第02章检查表有「日常／没人受伤／四格之内讲得完」，唯独漏了筛子③「只有他碰得上」——学生按表自检，第③条永远不查 |
| 41 | **例子挂在隔壁工序层上**（属于 §6.3c 那类「工序链」问题，落到小节里就是「与题意不符」） | 先把这个小节的主题写成一句「**这一节解决的是哪一步**」，再把节里每个例子标上它属于哪一步；标不上本节那一步的就是外来的 | 例子本身是真的、句子也通顺，只有把「本节主题」与「例子所属工序」并排看才露出来。实测第02章 P13（锁定麻烦 → 扩展方向 → 组内表决）的表决框尾句举「趁同学不在拿他的绳」——那是**他怎么解决**（第04章的事），而这一节还在挑麻烦／认卡点；用户判定「这一小节是麻烦与卡点，而非解决办法，与题意不符」 |

| 42 | **对照表某一列的两行填的不是同一类东西** | 拿**列名当尺子**，逐列问「这一列要填的是哪一种东西」（卡点＝岔子、怎么办＝他打算怎么做），再看每行填的落没落在这类里；同类里冒出**否定式收口**（没事／没出岔子／还行），就是断裂点 | 两格单读都通顺，单元格也标了红；但**红标只表示「这格要改」，不表示「这格填的不是这一列该有的东西」**。实测第04章 P24 的「卡点」列：V2 填真岔子（同学让他等一轮），V1 填「他一个人练熟了，**没事**」——填的其实是结局，与列名对不上；连读「拿走 → 没事」还会读成「偷了也没关系」，与全门课「不许有人吃亏」的口径撞车 |

**改法（一个通用的板块顺序）**：

`标准（①→N 逐条，每卡内留 ✅/❌）` → `逐条代入一个实例（带「顺序」列的表格，一条一行）` → `备选（想不出来时从哪几件里挑）` → `📎 承接下游（这一步做完，下一步产出什么，见 P0x）`。

- **重复的盒子并进标准卡**，别并排说两遍（「靠偷抢骗占便宜」原本单列在「淘汰这类」里，并进筛子②的 ❌ 行即可）。
- **实例要带顺序**：标准编 ①②③④，实例逐条跟着编，眼睛能顺着走下来——这就是「符合先后顺序」。
- **一个页面只留一处示范实例**，其余引用它（`📎` 样例条改为「填好的样子见 P14」，不要把内容再抄一遍）。
- 顺带核一遍**本章的盖章检查表**：横幅的成果 ＋ 小节的每条标准，都要能在检查表里找到一行；漏掉哪条就补哪条，别只补在「成果达标」卡里。
- **例子挂错工序层时「整句删掉」，别改写**（2026-09-16 新增）：层不对的例子改不动——它在那一层没有立足点，硬改成本节的东西等于重造一个例子。删掉后回头确认三件事：
  ① 这句承担的机制有没有别处兜住（本例「沾上就淘汰」由 P12 四个筛子里②「无人受伤」承担，删了不塌）；
  ② 这个例子在**它自己那一层**有没有落点（本例以「解法」身份活在附录 C 控点④「趁同学背过身把绳拿走」，所以整门课没丢东西）；
  ③ 删完这一句还成立不成立，须读一遍（本例剩「先问一句：「这条里有伤害吗？有人占便宜吗？」」，是一句完整的追问，够用）。
  **改完两份课件一起改**：同一个句子往往在讲台版与「按标准源另出的那一版」里逐字同时存在（本例两份都写 `沾上就直接淘汰，不进投票`），只改一份就留下两套口径。
- **反例格：先用「点出缺失」替掉含糊词，再跟上一格焊上因果**（2026-09-16 两轮收敛，别停在中间那版）：对照表里故意留下的那一格反例，别用「没事／还行」这类含糊词收口，要把「缺了什么」直接写出来。但**只点出缺失还不够**——第一版写成「他一个人练熟了，故事就收掉——没有卡点」，用户第二轮判定「前后逻辑还是不太通」：上一格是「趁同学背过身，把跳绳拿走」，这一格却从「他一个人练熟了」起步，中间少了「拿走之后东西就到了他手上」这一环，读起来像跳过去的；且「故事就**收掉**」是编辑行话，与破折号后半句的判断语域不搭。定稿：
  「**绳拿到手，他一个人练熟了，故事到这儿就结束——第四拍没有卡点**」——开头承接左邻那一格的动作结果，中间给 V1 实际写了什么，破折号后点出缺的那一拍。
  三条自检：① 首句能不能接上左邻那一格；② 有没有行话（收掉／收尾／流水账）；③ 收口有没有说清「哪一拍缺什么」。改完把同一个词的其他引用处一并同步（同页说明框、第04章 P21 的引例），否则全篇又是两套说法。
- 样稿侧同步：标准加了一步（如「逐条过筛」），样稿对应成果段也要出现这一步的结论（一行 `✓` 即可），否则并排读又是两套。

#### 6.3f 范例链 · 道具与承接专查：一件东西只有一个落点，一章开头只有一个入口

§6.3c 管「故事推不推得下去」，这一节管**支撑故事的那几件具体东西**和**章与章之间那条缝**。实例（2026-09-16，42 页课件，一轮查 5 类）：

| # | 缺陷 | 怎么查 | 为什么脚本查不出 |
|---|---|---|---|
| 22 | **同一件道具上下游是两个落点** | 把示范角色的每件道具 / 落点拉成一列，逐章比（绳丢在哪、书包在哪、对白写给谁）；搜容器词（柜 / 书包 / 抽屉）一次搜齐 | 每处单读都通顺。实测第02/03章写「打开储物柜，跳绳不见了」、第05章四格画「一只手伸进空书包」，样稿的修改记录又写「从『翻找书包』改起」——三处三件事，学生不知道到底画哪个 |
| 23 | **章与章之间没有入口** | 数 `🔗` 承接框的个数：**每一章开头都该有一条**（接上一章那件产物） | 承接句是内容，不在结构检查项里。实测只有第02、05章有，第01/03/04/06/07 章开头直接进正文，学生不知道这一章的起点是什么 |
| 24 | **尺子 / 标准上挂着别人家的例子** | 把「第 N 条」的标题与它举的例逐条对读，例是不是这条标准上的事 | 标题与例子各自都成立。实测第04章尺子③标题写「看**第三格**有没有『诶？』」，举的却是第四格的事（借到了却要等一轮） |
| 25 | **同页两条规则打架** | 把同页所有「要 X」抄成一列，看有没有一条说「X 要变」、另一条说「X 不能变」 | 两条分处不同板块，各自都讲得通。实测 P29「路径二：要**换比例**」↔ 同页锚点「身形比例**不能**这格高那格矮」 |
| 26 | **上游让学生「自己补 X」，可 X 已经由 AI 产出** | 把这一章「步骤 N」的动词与同一页「指令」的要求逐条对表 | 步骤与指令分栏书写。实测 P09 步骤③「再自己补上愿望和弱点」，而同一页指令①本来就要求 AI 给出「一个具体的愿望＋一个弱点」 |

**改法定式**：

1. **道具先判「学生真会画出来的是哪一件」，再改上游。**判据不看哪处出现得早，看**下游有几处锚点**：实测「空书包」在下游有 8 处（prompt 四格内容、`.fourmap` 版式、附录 A 生成例、样稿 alt…），而道具本身又是角色的标志物（每格都要出现）——所以改上游的第02/03章，不改下游。**旧落点别急着删**：柜子在这次改里留下来当场景，并继续撑住筛子③的论证。
2. **每章补一条 `🔗` 承接框，放在 `page-body` 第一个子元素**，句式统一 `🔗 接第0N章<那件产物>：上一章定了什么 → 这一章做什么`。补完全文搜一次断口（把 `🔗 接` 的条数与章数对比，本课为 7 条接序章→01…→07）。
3. **标准与实例错位时，先看例能不能改挂**：能就改例（本例把「第三格」的格号去掉、例子换成第三格真有的意外），改不动再动标准。
4. **「变 / 不变」用参照物区分**：两条规则打架多半是没说清参照物——「换比例」说的是**与参考图相比要换掉**，「不能这格高那格矮」说的是**四格之间前后一致**；补一句「换完还得回头核对，四格之间前后一致」两条就并存了。

**产物**：记「哪件道具 ＋ 旧落点几处 / 新落点几处 ＋ 改上游还是下游 ＋ 承接框补了几条」，改完搜一次旧写法确认零残留。

#### 6.3g 章名与工序链专查：章名要能读出「这是第几道工序」

递进型课程（后一章拿前一章的成果接着做）最容易坏在**章名的命名轴**上。实例（2026-09-16，第02–05章）：

| # | 缺陷 | 怎么查 | 为什么脚本查不出 |
|---|---|---|---|
| 27 | **章名混用两套以上命名轴** | 把导航里每条章名抄成一列，问一句「它属于哪一类：阶段名 / 版本名 / 成品名」 | 每条章名单独看都成立。实测 02「故事发生」是**阶段名**、03「V1 失败稿」04「V2 定稿」是**版本名**、05「四格成稿」是**成品名**——三条轴并排，导航上读不出递进关系 |
| 28 | **两个「终点」打架** | 导航里数一数有几个词是「做完」的意思（定稿 / 成稿 / 完成 / 出厂） | 词义都通。实测第04章叫「V2 定稿」、第05章叫「四格成稿」——第04章既然「定」完了，第05章还「成」什么 |
| 29 | **同一个版本号挂在两种不同产物上** | 把带 V1/V2 的地方逐处点开，看它标的到底是哪一件东西 | 单处读都自洽。实测 03 交的是「四格**脚本**」、04 交的是「四行**提纲**」——V1/V2 看起来像同一张纸的两版，实际是两层产物，学生按名字对不上 |

**改法**：

1. **一个课程只用一条命名轴。**递进型首选**动词轴**：`02 定麻烦 → 03 写初稿 → 04 改一稿 → 05 画成稿`——四个三字词对齐，导航一眼看出是一条链。阶段名（「故事发生」这类）与版本名（「V1 失败稿」）都别混进来。
2. **章名与产物名不复用同一串字。**产物名（V1 失败稿 / 四格成稿）留在「要交的六件」卡片标题、展板分块、清单表里；章名换成工序动词。两边同字时，学生分不清「第03章」说的是**章**还是**交的那件东西**。
3. **每一章显式补齐三段：拿 → 做 → 交。**`🔗 接第0N章<那件产物>` 只是「拿」，末尾必须再补一句 `<b>交出去</b>：X——第0N+1章就拿它做 Y`。只写「拿」不写「交」，链子就断在半截，学生读完这一章不知道自己的东西要递给谁。
4. **在课程开头挂一张四行表**（序章「要交的东西」那一页），把这条链的「拿上一章的 / 这一章做的事 / 交出去」三列一次列全——全篇要有**唯一一处**把链说明白的地方，不能只靠一章一句拼。
5. **递进必须在同一层。**版本号只能挂在同一种东西上；若上游交 A、下游交 B，就把两层的关系写明（例：「四行提纲是故事四拍的**要领版**，四格脚本是同样四拍的**逐格版**——同一部故事，粗与细的差别」），别让 V1/V2 看起来像同一张纸的两版。
6. **章名改动要四处同改**：topnav、通关阶梯、章横幅 `pnum`、序章卡片 `chchip`。漏一处就出现两套名字。改完跑 `check_course.py` 确认页数 / 横幅 / 锚点不变（只改字不动结构，三组数字应当一模一样）。

**产物**：记「旧章名 → 新章名 ＋ 命名轴是什么 ＋ 哪几处同改」，并单独核一遍样稿有没有引用章名（**样稿按成果编号排版时通常零引用，不必同步**）。

#### 6.3h 教案 / 课程大纲 ↔ 课件对齐专查：成体系的表别只剩半张

一套课常有两份文档：**教师课程大纲（md，标准源）＋ 课堂课件（html，执行件）**，还有一份学生样稿。三者共用同一批专名与清单。实例（2026-09-16，拿 14KB 大纲过 45 页课件）：

| # | 缺陷 | 怎么查 | 为什么脚本查不出 |
|---|---|---|---|
| 30 | **大纲里成体系的表，课件里只剩半张** | 把大纲的每张表按「列」对读课件同一主题的板块：列少了几栏 | 课件那半张自己读得通。实测大纲的岗位表是「管什么 / 每章交出什么 / 明确不许做」三栏，课件只写了「管什么」——四个岗位没一个说得出「不许做」 |
| 31 | **大纲里有「不达标怎么办」，课件只在前两章有** | 逐章数盖章块里有没有「没过 / 不达标怎么办」一句 | 每章单读都完整。实测第01、02、05章有，第03、04、06、07章没有——「带学生一步步走完」就成了空话 |
| 32 | **大纲有可查的矩阵，课件只写一句规则** | 凡是「每章轮换 / 按人数分档 / 逐周推进」这类规则，问一句「老师能不能照这句话直接排出来」 | 规则本身没错。实测课件只写「每章顺时针换岗」，老师现场得自己推七章；大纲里有现成的 A/B/C/D × 七章矩阵 |
| 33 | **大纲写明了前置条件，课件漏了** | 找大纲里的「才 / 之后 / 必须先」这类条件词，逐条回课件核 | 半句话读不出缺。实测大纲写「**盖章后才轮换岗位**，没盖章的组下一章先补齐、不轮换」，课件只说「盖完章换岗」——漏了「没盖章怎么办」 |
| 34 | **三份文档共用的清单，标题逐字不同** | 把同一份清单（五问自检、四道尺子、四个筛子）在三处抄出来并排比 | 每处单读都自洽。实测「五问自检」课件是「①拿去给陌生人看，他能复述吗…」、样稿与大纲是「①看得懂吗…」——并排读才发现不是同一套 |
| 35 | **大纲落后于课件（改过名 / 改过口径，没回标大纲）** | 把大纲里所有专名与数字抄出来，逐个在课件里搜；搜到下位版本就是落后 | 大纲本身自洽。实测课件章名已统一成 `定麻烦/写初稿/改一稿/画成稿`、参考图已改成「四格参考图」，大纲还写着旧章名与「逐格单格参考图」 |
| 36 | **标准源自带的口径冲突，被逐字搬进课件** | 把标准源里每个专名（弱点、卡点、身份、锚点）抄出来，在课件全文搜，数同一个字段出现几次、每次上下文说的是哪个字段 | 那一行单看自洽。实测大纲附录写「弱点是话到嘴边张不开嘴」，课件正文却有 12 处写「一到人多的地方就紧张到发抖，连话都说不利索」，而「话卡在喉咙里，他张不开嘴」是第02章的**④卡点**那一格——照抄等于把弱点写成卡点；偏偏故事发动机（愿望×弱点）、P11 的预判、P19/P23 的「踩上弱点」全靠那个弱点扛着 |
| 37 | **四条红线里有两条说的是同一件事** | 把红线并排读，看有没有一条的从句被另一条覆盖；再回标准源核那条的原意落没落地 | 四条都在、都成立，只有并句读才发现。实测红线①尾句「也不照着某位画师的风格描」＝ ③「不照搬侵权画风」，而大纲①的原意（角色必须从 AI 候选里改出来）反倒漏了 |
| 38 | **页标题列的件数与页内版块对不上** | 把标题里用顿号列的那串，与页内卡片标题、以及下一章自检清单逐个对 | 标题只是文案，不参与结构校验。实测 P30 标题写「对白、编号、落款、**署名**」，页内四张卡却是「对白框／四格编号／落款／**AI 标注**」，P31 自检清单也写「AI 标注」——标题里那个「署名」既孤立又与「落款」同义 |
| 39 | **标准源里的用词撞上执行件的语域红线** | 把标准源（大纲）的章名与专名逐个过一遍执行件的禁用词表 | 标准源自己读得通。实测大纲章名「07 漫画展 · 发布与**复盘**」里的「复盘」正在课件禁用词表内（职场语汇，一律改「回头看」），照抄进课件会被 `check_course.py` 第 7 项拦下 |

**改法**：

1. **先判定「以哪边为准」，再动手。**有用户明确指令的那几处（改名、改口径）**以课件为准**；大纲只是没跟上，别拿旧大纲去回退课件——那一退就把用户前几轮的指令作废了。**落后点在回复里逐条列出**，请用户决定要不要回写大纲，不擅自改非课件文档。
2. **只补课件缺的，成体系地补。**大纲里成表的东西，补进课件时也补成表（多补一列 / 一栏），不要降成一句话塞进段落。
3. **每章的盖章块是固定件：成果达标 ＋ 全员说得清 ＋ 不达标怎么办。**第三段任何一章缺了都要补，措辞用本章自己的例子（「一条问题都找不出来怎么办」「哪一问没过怎么办」）。
4. **靠人数 / 章节组合出来的东西要给矩阵。**岗位轮换、分档推进这类，给一张「章 × 成员代号」表，比一句「往后挪一格」有用得多；表里的值直接等于各章横幅的成果名。
5. **教师侧的资产可以直接补成附录页。**控点的处理办法、教师控点、示范范例链这类只在教师手上用的东西，挂在**附录末尾**（新开一节）最省事——**不牵动任何既有页码与跨页引用**，只让页数 +1。
6. **三份文档共用的清单，改一处要改三处。**五问自检、四个筛子、四步复述链、落款口径都在此列；改完逐字并排核一遍。
7. **反向也要核一遍：课件「落后于大纲」才要补，「领先于大纲」的那几处别回退。**拿大纲逐条过课件时先分成「课件缺」与「大纲缺」两栏；凡是有用户明确指令在前的那几处（改名、改口径），**以课件为准**，只在回复里留一张「大纲落后点 / 以哪边为准 / 要不要回写」的表请用户拍板，不擅自动非课件文档。判据：**这一处有没有用户指令支撑。**
8. **标准源与执行件撞词时，看哪个字段是承重的。**同一个属性在两份文档里措辞不同（弱点 vs 卡点、身份 vs 住址），别默认改执行件——把该属性在课件里出现的每一处拉出来数：**被别处引用最多、撑着某道工序的那一版才是正解**，把另一版按它改，并在回复里点明标准源同一处也要跟着改。2026-09-16 实测：跳跳的弱点在课件里有 12 处是「一到人多的地方就紧张到发抖」，只有大纲附录那一行写成「话到嘴边张不开嘴」——改的是课件那 1 处，同时提请用户回写大纲。

9. **「按标准源另出一版」＝ 另存新文件，原版一个字不动（2026-09-16 新增）。**用户说「保留该版本，同时按照大纲再出一版」时，做法是复制一份带版本标识的新文件（如 `·大纲版.html`），**只在副本上改**——锁步对里的原版与样稿都不动，交付前用字节数核对原版未被污染。动手前必问两句，它们决定全篇：① **口径冲突以哪边为准**（标准源 vs 执行件——本轮 4 处：章名轴、参考图粒度、展板顺序、产物名）；② **密度档位**（讲台版 200–230 字 / 备课版 300–360 字，见 §4.1b）。执行顺序照「**先铺同名字、后改内容块**」：章名这类一个词散在 6–8 处的，先用一张映射表把 topnav、两处阶梯、章横幅 `pnum`、卡片 `chchip`、小结表格一次替换到位（本轮 31 处），再动 P28／P35 这类整块内容——顺序反了会一边改一边漏。改完**交一张差异表**（哪几处与原版不同、以哪边为准、标准源要不要回写），并扫一遍标准源用词有没有撞执行件的语域红线（见缺陷 39）。

**产物**：两列清单——「大纲有的 / 课件没有 / 怎么补」与「大纲落后于课件的点 / 以哪边为准 / 要不要回写大纲」，改完跑 `check_course.py` 并复核页数变化符合预期（两次实测：44 → 45 只多附录一页；反向核查一轮改 3 处、页数不变；另出一版一轮改 40 余处、页数横幅锚点三组数字全不变）。

## 自我进化机制（遵循 `cyx-skill-evolution` 通用条款）

**本技能不是一次写死的。** 用户拿本技能做课件时提的每一条修改意见，都可能是适用于**所有后续课件**的规则；把它挑出来写回本文件，本技能才会越用越准。判定与留痕规则见 `cyx-skill-evolution`，本节的落点表只列本技能自己的。

**触发**：用户对已交付课件提意见（结构 / 页面 / 组件 / 文案 / 页码 / 语域）；同一类意见出现 ≥2 次 → 默认写法错了，从「建议」升为强约束；我主动发现错命令、缺步骤、前后矛盾 → 不等指令当场修。

**落点映射**（按本技能实际结构）：

| 反馈类型 | 典型原话 | 改本文件哪一节 |
|---|---|---|
| 编排模式 | 「不要时间，按章节来」「锁总时长」 | 第 1 步 + 第 2 步（选错模式 = 全套骨架白做） |
| 编号与页码 | 「页码乱了」「章号对不上」 | 第 2.5 步（双编号体系，改页码必须用脚本） |

## 已知限制

- 模板无外链、无 `<script>`（纯静态 HTML+CSS），因此可离线双击打开；也意味着默认没有 JS 交互（check-list 用原生 checkbox）。**唯一例外**：用户明确要求「说课点开才看」或「右下角要有跳转导航」时，按第 3 步的 `.lecture` / `.dock` 加内联 `<script>`——此时 `check_course.py` 第 17 项会报 `无 <script>` FAIL，属设计批准的偏离，交付说明里写明即可，别去改脚本糊掉这一项。
- 渲染抽查优先 `agent-browser`；本机若未安装（需全局装包 + 下载 ~500MB Chromium，常见情况），走第 7.1 节的「本机 Edge 无头」降级路径，**不要因此跳过渲染验证**。
- 无网络且本机无 Edge 时，才退化为第 6 步静态检查 + 人工抽查，并在交付说明里写明未做渲染验证。
