# 派生文档对齐内容基准（cyx-doc-align-baseline）

一份课件家族里常有四五份文档：主课件 md（**内容基准**）、课件 HTML、学案、教师讲课稿、课程大纲、旧副本。
基准一改（加一页、合并两页、把某岗位口径换掉），派生文档就全体漂移。
本技能只干一件事：**把派生文档拉回基准**。

## 第 0 步：先问清「对齐到哪一步」

必须先用 `AskUserQuestion` 定死两件事，**不要自己猜**：

| 问题 | 典型选项 |
|---|---|
| 对齐到哪一步？ | **① 只对齐口径与事实（保留原文体例）** ／ ② 连体例一起改成基准的格式 |
| 改成哪份？ | 原地改 ／ 到目标目录新建 ／ 另存副本 |

**默认走 ①**。①②差别极大：② 等于重写一份，① 才是"对齐"。
用户说"保留体例""只改口径"时，**一个字都不许动正文写法**——包括段落顺序、标题措辞、说话风格。

## 第 1 步：把基准读全，列「待对齐项」

逐项比对，做成一张清单（这是本技能的核心工作量，别跳）：

| # | 待对齐项 | 怎么查 |
|---|---|---|
| 1 | **页数声明** | 头部「对应课件 N 页」、目录区间、篇末「共 N 页」 |
| 2 | **编号体系** | 每章从 `.0` 还是 `.1` 起；附录是 `A.x` 还是 `8.x`；序章过关页挂在哪一章 |
| 3 | **页数增减** | 有没有合并/拆分页；哪一页之后全体顺移 |
| 4 | **术语族** | Grep 基准的**独有词**（在派生文档里为 0 的那些），逐个替换 |
| 5 | **禁项图标** | 基准规定"md 不带 emoji"时，扫键帽 `U+20E3`、变体选择符 `U+FE0F`、`U+1F300`–`U+1FAFF` |
| 6 | **页脚格式** | `<p align="right">0.0 ｜ 第 1 页</p>` → `> **0.1**　｜　第 1 页 / 共 48 页`（全角空格 `\u3000`） |
| 7 | **跨页引用** | 正文里所有 `X.Y`：本章主线链、总览页"关联页"列、附录"在哪页"列、「见 2.3」「翻 0.1」「回去看 0.4」 |
| 8 | **代码围栏** | 基准是 ` ```text `，派生文档是裸 ` ``` ` → 统一 |
| 9 | **附录 / 小节编号** | `A.0→8.1`、`A.1→8.2`、`A.2→8.3` |
| 10 | **不许动清单** | 逐字对照基准的特殊块（AI 指令、表格数值）——**这些是锁定内容** |

**判据：不动这条，读者会不会被误导？** 会（页码、页数、口径、术语）→ 改；只是排版习惯不同 → 不动。

## 第 2 步：建一次性编号映射表（**禁逐个 replace**）

> 踩过的坑：用"从大到小逐个 `replace`"重编号，前一轮的目标值变成后一轮的输入，41 个 id 全撞成同一个（重编号事故的标准形态）。

正确做法——**一次映射，不迭代**：

```python
REF = {}
for k, v in [("0.0","0.1"), ("0.1","0.2"), ("0.6","0.7"), ("0.7","0.7"), ("0.8","1.1")]:
    REF[k] = v                      # 合并页：两个旧号都映到同一个新号
for i, v in enumerate(["1.2","1.3","1.4","1.5","1.6"]):
    REF[f"1.{i}"] = v               # 章内插页的那一章：+2
for ch, mx in [(2,5),(3,5),(4,5),(5,4),(6,3),(7,4)]:
    for i in range(mx+1):
        REF[f"{ch}.{i}"] = f"{ch}.{i+1}"      # 其余章：+1
REF["A.0"], REF["A.1"], REF["A.2"] = "8.1", "8.2", "8.3"
```

**两个易漏点**：

1. **章内偏移量可能不同**。某章若在开头插进了别章的一页（如"序章过关"被挂到第 01 章下），它的映射是 `+2` 而不是 `+1`。**逐章验算，别假设统一 +1**。
2. **合并页要单独处理**。两个旧编号映到同一新编号时，形如 `（0.6、0.7）` 的并列引用会变成 `（0.7、0.7）`——先做 `（0.6、0.7）→（0.7）` 的预处理。

## 第 3 步：按行分派，页脚与正文分开走

页脚里的 `X.Y` 和正文里的 `X.Y` **映射规则不同**（页脚还要改页序和总数），
而且转成新页脚格式后，`**0.1**` 里的点号会被正文正则再吃一次 —— 所以**必须按行分派**：

```python
RE_FOOT = re.compile(r'^<p align="right">([0-9A])\.([0-9]) ｜ 第 (\d+) 页</p>$')
RE_REF  = re.compile(r"(?<![\w.\-/])([0-9A])\.([0-9])(?![\w])")   # 避开 2026-09-17、v1.0、3–4

for ln in text.split("\n"):
    m = RE_FOOT.match(ln)
    if m:                                   # 页脚行：查表 + 页序换算
        lab, n = f"{m.group(1)}.{m.group(2)}", int(m.group(3))
        newn = n - 1 if n >= SHIFT_FROM else n      # SHIFT_FROM = 顺移起始页
        out.append(f"> **{REF[lab]}**\u3000｜\u3000第 {newn} 页 / 共 {TOTAL} 页")
    else:                                   # 正文行：只映射编号
        out.append(RE_REF.sub(lambda mm: REF.get(f"{mm.group(1)}.{mm.group(2)}", mm.group(0)), ln))
```

- **页序换算**与编号映射是两件事：合并页丢掉一个页码后，`第 8 页起全体 -1`。
- **被合并掉的那一页的页脚直接丢弃**，别改名留着（会多出一个页脚）。

### 结构改动：合并页 / 挪页

用**占位符**过渡，最后才写入成稿，避免成稿被后续正则二次加工：

```python
MERGE_MARK = "@@MERGED_0_7@@"
a = text.index("## 0.6 ｜ …");  b = text.index('<p align="right">0.7 ｜ 第 8 页</p>') + len(...)
text = text[:a] + MERGE_MARK + text[b:]
# …跑完所有编号/术语/图标变换…
text = text.replace(MERGE_MARK, 手写的合并页)   # 成稿里的编号已经是最终值
```

**合并页要手写**，不能拼接——六块/说课三段这类体例要求一整页只有一套块。
**挪页**（如"序章过关"移进第 01 章）用 `text.replace(anchor, block + 分隔 + anchor)`：
切出来的块带着旧编号，放进正文流里让正则一起处理；随后清理两段 `---` 相邻产生的连续空行。

## 第 4 步：术语与禁项

- **术语替换用整行/整句精确匹配**，别用裸词 `replace`（"一人一岗"里的"一岗"、"岗位"都会被误伤）。
- 逐条写成 `(旧串, 新串)` 列表跑，并**打印每条命中的次数**——`hit=0` 说明上下文没对上，必须回查。
- **去图标只删图标本身 + 紧邻它的一个空格**，不做全局空格压缩（全局压缩会把 `**说课**`、箭头链 `① → ②` 一起搞坏）。

## 第 5 步：跑校验组（`scripts/check_alignment.py`）

```bash
python scripts/check_alignment.py --out <本稿> --base <基准md> --pages 48
```

八项全绿才算完成：

1. 二级标题数 = 页数，且编号连续（`0.1…0.7 / 1.1…1.6 / … / 8.1…8.3`）
2. 页脚数 = 页数
3. 页码 `1..N` 严格单调
4. 页脚里"共 N 页"唯一值 = 页数
5. 旧编号体系残留 = 0（`0.0 `、`0.8 `、`A.0`、`9.` …）
6. 旧术语族残留 = 0，禁项图标 = 0
7. 锁定块（指令 ` ```text ` 等）与基准**逐字一致**（空白归一后）
8. 头部"共 N 页"/"对应课件 N 页"与实页数一致

**第 7 项最容易漏**：指令这类锁定块只差 1 个标点（如 `，` vs `——`）也算不一致，`len` 差 1 就报警，用 `difflib` 打出 opcode 定位。

## 第 6 步：交付与登记

- 交付 `present_files`；正文说明**改了哪几类、基准是哪份**。
- **回写项目记忆**：把新交付的派生文档登记进"同步清单"（基准一改，这份也要改），
  否则下次改页码时它第一个被忘掉。

## 第 7 步：按新事实回填（基准没改，是新事实比文档新）

基准不动，但你手里多了一批**新事实**（产品新界面截图、官方新材料、用户口述的实操流程），要同步进多份同族文档时，走这套：

1. **先把落点表列全再动手**。逐份写清「这份的第几处要跟着改」，不要边看边改——三份文档改到一半发现落点漏了，回头很难判断哪里改过。
2. **回填内容按来源标级**。截图得来的事实一律标「界面观察」，与官方口径分列，不写成事实基线；官方材料支撑的才进基线。
3. **顺手查自相矛盾**。新事实最容易暴露旧表述与同文档别处打架（例：一处写「不能复用历史资产」，同文档资产页却写支持「从资产库选择」）。**判据：同一件事在文档里是否只有一个说法**——不一致就按新事实统一，别留着两说并存。
   - **同一个事实会在不同「形态」里被重写成不同措辞，改一处必须按形态逐个扫**：总览表单元格、分档对照表、正文小节及其小标题、痛点/局限框、术语表定义、文档信息与变更记录。扫不干净的典型症状——同一个能力在同一份文档里，一处被排成「最低一档」，另一处又被说成「中间态」。
   - **能力／档位的定性一改，分档结构要跟着重排**。用户说「A 的能力与 B 基本一致」时，要动的不是一句话：原来把 A 单列成最低一档的对照表要合并或重排（四档 → 三档），依赖档位数字的正文（「分四档——①②③④」）要重编号，每份文件里对应的档位行都要同步。改完回扫三件事：档位编号是否连续、有没有残留的旧档位说法、各份文件档数是否一致。
   - 实战例（2026-09-23）：把「阶段2 一键成片是黑盒、用户改不了内部细节、可控性最低」改成「与阶段3 出海转绘同档」后，连带动的是——总览表单元格（三份文件各一处）、主线1 的分档对照表、阶段2 痛点小节标题、阶段5 那行的「解决全自动黑盒」、术语表「黑盒」的定义、以及各文件的变更记录。只改用户圈出的那一句，等于把矛盾从一处搬到另一处。
4. **文档自称的元叙述要跟着改**。写过「本文档未新增任何原稿没有的事实」这类加工自述的，本轮补了事实就必须改掉，否则留下假声明。
5. **界面标签优先于文档自造词**。产品里的 Tab / 按钮怎么叫，文档就怎么叫（如界面叫「分镜版」就不要写「分镜页」）；改的时候一次改净，别半新半旧。
6. **不要顺手升版本号**，除非全文档所有版本标记（头部徽章、文档信息表、页脚、导语）能一次改全。只改两处、漏两处，比不升更糟——宁可把变更写进已有的版本说明行。
7. **回填前先 `Grep` 旧串**。同一项目反复迭代时，要改的那句可能在前一轮已经改过了。动手前先搜一次 `old_string`：命中才改；不命中就先 `Read` 确认（多半是前轮已改，或措辞已被订正），**跳过即可，别当成失败反复重试**。判据：`Edit` 报「String to replace not found」≠ 内容漂移，也可能是前轮已落盘。
8. **跨入口共享的能力，一处写全、其余处交叉引用**。同一个操作集（如分镜版卡片的拖动排序/选中/编辑/复制分镜/删除、协作与分享弹窗）常被多个产品入口共用；不要在每份文件、每节里各写一套（必然口径漂移）。挑最主要的一处写全，另几处只加一句「与 X 一致／三种项目一致」。收尾时 `Grep` 该能力的关键词，确认三份文件命中数对得上预期。
9. **往既有表格里补条目，要插回它该在的位置，不许 `append` 到表尾**。表格常自带排序纪律（如需求表按 `P0 → P1 → P2` 分段、待确认表按编号连续），而新条目最容易被顺手加在最后一行——这就把表本身排好的顺序破坏了，且用户一眼就能看出来（表尾挂着一个 `P0`）。补行前先看这张表按什么排，再把新行插进对应段。**判据**：改完抽一遍 `(编号, 优先级)` 序列确认单调，长表用脚本抽、别靠眼睛扫（正则示例：`<tr><td>([A-H])(\d+)</td>.*?<td>(P\d)</td>`，再断序列非降序）。**编号不随排序重排**：编号是稳定标识，被「P0 范围」行、正文、附录交叉引用（如 `导出 C6`、`画风比例 G3`），重排会连锁破坏引用；文档既有风格本身就是「按优先级排行、编号不重排」。

> **本机落盘陷阱（Windows · Edit 工具）**：对**同一个文件连续多次** `Edit`，会返回「Successfully edited」但**静默不落盘**。
> 可靠节奏：**每轮每个文件只改一处，多份文件并行**；每轮结束用 `Grep` 复验**新串**是否在盘（别只复验旧串——旧串可能本来就还存在于别处）。
>
> 另一类失败：`Edit` 报 **「String to replace not found」**——几乎总是 `old_string` 凭记忆拼的、与盘上文本有细微出入（少一个「点击」、多一个标点、全角半角不同）。**不要猜着重试**：先用 `Read` 把该区块重新读一遍，用**最新原文**重拼 `old_string` 再 Edit，一次过。

## 一页速查：常见漂移成因

| 现象 | 成因 |
|---|---|
| 全文页码差 1 | 基准合并过两页，派生文档没跟着 |
| 某章往后差 2 | 该章开头插进了别章的一页 |
| 页脚总数不一致 | 页脚错位（上一页的页脚落在下一节标题前），删页时才暴露 |
| 术语半新半旧 | 只改了表格没改口播/页底收口/引导语；**每处话术都要单独 Grep** |
| 表尾挂着一个 P0 | 后补条目直接 `append` 到表尾，没插回该表自己的排序段（需求表按 `P0→P1→P2` 分段） |
| 图标"删干净了"但排版坏了 | 用了"先删图标再全局压空格"两步法 |

## 自我进化机制（遵循 `cyx-skill-evolution` 通用条款）

**本技能不是一次写死的。** 用户拿本技能做文档对齐时提的每一条修改意见，都可能是适用于**所有后续对齐任务**的规则；把它挑出来写回本文件，本技能才会越用越准。判定、留痕、回退规则见 `cyx-skill-evolution`。

**触发**：用户对对齐结果提意见（页码、编号、术语、体例、锁定块）；同一类漂移出现 ≥2 次 → 说明是**判据缺了**而不只是这一处漏改，要补进「一页速查」并升为强约束；我校验时发现脚本查不出的漂移类型 → 不等指令当场补检查项。

**落点映射**：

| 反馈类型 | 典型原话 | 改本文件哪一节 |
|---|---|---|
| 基准选择 | 「和哪份对齐」「以哪边为准」 | 第 0 步（先问清「对齐到哪一步」） |
| 待对齐项遗漏 | 「这处也该跟着改」 | 第 1 步（读全基准、列待对齐项） |
| 编号与页码映射 | 「页码差 1」「编号对不上」 | 第 2 步（一次性映射表）+ 第 5 步第 1–4 项 |
| 表内行序 | 「要 P0 在前」「表里顺序乱了」 | 第 7 步规则 9（补条目插回对应优先级段）+「一页速查」 |
| 结构改动 | 「这两页合并」「这页挪过去」 | 第 3 步（占位符过渡、合并页手写） |
| 术语与图标 | 「这个词还没换」「图标删坏了」 | 第 4 步（整行精确匹配、只删图标与紧邻一个空格） |
| 校验项缺失 | 「这个错没查出来」 | 第 5 步 + `scripts/check_alignment.py` 新增断言 |
| 同步清单 | 「这份也忘了改」 | 第 6 步（回写项目记忆的同步清单） |

**沉淀后必做**：① 新漂移成因同时补进「一页速查」与 `check_alignment.py` 的对应项（**只写前者，下次仍查不出**）；② 在 `cyx-skill-evolution/references/feedback-log.md` 追加一行（本技能无自带账本，写通用账本）；③ 一句话告知用户「这条记进 cyx-doc-align-baseline 了」。
