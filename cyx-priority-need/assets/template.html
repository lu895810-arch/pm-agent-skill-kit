逐条需求评估

需求1：文本对话能力

需求描述：用户输入文字，调用大模型 API 返回对话回复。

优先级P0
一句话结论产品核心流程，没有该功能用户无法完成核心交互，V1 必须上线。
  • 用户价值：全部用户使用，是用户使用产品的核心目的。
  • 业务价值：支撑核心留存，无此功能产品不存在。
  • 依赖关系：无依赖。
  • 风险提示：依赖第三方大模型 API，需做好超时、错误兜底。

RICE 得分：80

建议：V1 必须优先保障，提前做 API 压测与异常兜底。

需求2：虚拟人换装皮肤

需求描述：用户可以切换虚拟人物外观皮肤。

优先级P2
一句话结论属于体验加分功能，不影响核心对话流程，V1 资源充足再考虑，资源不足延后。
  • 用户价值：仅部分用户需要，不影响核心任务。
  • 业务价值：提升好感，但不影响 MVP 验证。
  • 依赖关系：依赖虚拟人基础渲染模块。
  • 风险提示：美术资源投入大，投入产出一般。

RICE 得分：24

建议：V1 不纳入开发，放到 V2 版本规划。

整体评审建议

  • P0 项目检查：当前 P0 仅 1 项，合理，无冗余 P0。
  • 依赖风险汇总：换装功能依赖虚拟人渲染，渲染模块本身需评估优先级。
  • 资源评估：当前人力可轻松承载 P0。
