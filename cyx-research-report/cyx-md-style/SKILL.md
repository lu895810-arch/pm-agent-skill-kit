# Markdown 报告写作风格（cyx-md-style）

## Purpose（目的）

把一份已交付报告（《AI 教育厂商调研总结报告》）的**内容侧风格**固化成可复用规范：报告**怎么搭骨架、怎么分层、怎么标记、怎么措辞、怎么论证、怎么标口径**。

与另两个 skill 的分工：

| skill | 管什么 | 不管什么 |
|---|---|---|
| `cyx-md-style`（本文件） | **写什么、怎么组织成 Markdown**——结构、层级、表格、语言、论证、口径 | 渲染后的视觉 |
| `cyx-html-style` | 渲染成 HTML 后的**视觉与通用语言约束**——暗色科技风配色、组件类、去 AI 味 | 结构的搭建顺序 |
| `cyx-research-report` | 报告**方法论**——数据可信红线、脚注规范、论证链路、多格式交付链路 | 逐句写法 |

**关系**：本 skill 是内容侧的「怎么写」，`cyx-html-style` 是呈现侧的「长什么样」，`cyx-research-report` 是上游的「凭什么这么写」。三者叠加使用；单写 Markdown、不做 HTML 时，只用本 skill + `cyx-research-report` 即可。

## When to use（何时触发）

- 用 Markdown 写**调研报告 / 行业分析 / 竞品盘点 / 总结报告 / 复盘**。
- Markdown 作为**唯一事实源**，后续要转 HTML 与 Word。
- 用户说「按这份报告的风格写」「要分点、有框架、有章法」。
- 多人分头调研、需要把各条线的产出合并成一份统一体例的报告。

不触发：纯 HTML 视觉需求（走 `cyx-html-style`）、代码文档、README。

## How to use（如何使用）

1. 按「一、结构骨架」把报告搭成五段，**先定骨架再填内容**。
2. 按「二、层级与标记」排布标题、表格、加粗与引用块。
3. 按「三、语言规范」与「四、逻辑与口径」逐段写。
4. 交付前过「五、交付前自查清单」。
5. **交付后**：用户提的任何修改意见，先判通用性，再把通用项按「六、自我进化机制」回写本文件——本 skill 靠这一步越用越准。

## 一、结构骨架：五段式

报告的段落顺序固定为**结论 → 规律 → 明细 → 佐证 → 行动**，读者从「你的判断」读到「你的依据」，最后才是「下一步」。

| 部分 | 回答什么问题 | 标题写法 | 内部骨架 |
|---|---|---|---|
| 第一部分　结论 | **你的判断是什么** | `## 第一部分　调研结论（总体）` | 核心结论 → 分档速览表 → 逐档依据 → 完成度汇总 |
| 第二部分　规律 | **横向看有什么共性** | `## 第二部分　……（全公司视角）` | 每个小节一个横向维度（怎么建 / 怎么合作 / 课程什么样 / 钱怎么收） |
| 第三部分　明细 | **逐家逐项的细节** | `## 第三部分　分模块调研内容` | 按调研线或对象分组，每组＝速览表 + 逐家详情 + 组小结 |
| 第四部分　佐证 | **这些结论怎么来的** | `## 第四部分　附录：各组调研方式与产出` | 速览表 → 逐组过程详述 → 资料完备度 |
| 第五部分　行动 | **接下来做什么** | `## 第五部分　待办与线索跟进` | 勾选框清单，每条落到对象 + 动作 |

**四条骨架纪律：**

1. **先总后分**：每一部分先给数量化结论（「按匹配度分五档：7 家 / 2 家 / 8 家 / 4 家 / 1 家」），再展开依据。不许把几十条平铺列表直接摆上来。
2. **结论不与规律重复**：第一部分只留**结论 + 分档依据 + 完成度**；所有横向归纳（怎么建、怎么合作、课程、收费）只在第二部分出现一次。同一批内容写两遍，读者会以为换了内容。
3. **过程与产出后置**：调研方式、产出物清单、资料缺口属于佐证，放第四部分，不挤在结论里。
4. **行动项单独成部分**：第五部分才写「待回访 / 待索取报价 / 待纠偏」。正文不下行动判断（见「三」）。

**部分导语只写一行**，用 `>` 引用块交待范围与内容，不写「本部分将……」：

```markdown
## 第二部分　AI 教室建设与合作模式（全公司视角）

> 覆盖 24 家厂商中有实质 AI 教育业务的部分（重点为 A 类 7 家加 B 类 2 家），讲清「怎么建教室、怎么跟学校合作、课程长什么样、钱怎么收」四件事。
```

### 第零部分：前置现状对照栏（可选）

需要回答「我们的现状是否合理」时，在五段之前加一栏，编号独立于正文 `1`–`N`，固定三段式：**现状 → 坐标 → 逐条对照＋结论**。

```markdown
## 第零部分　我们的现状与行业对照

> 起步路径对得上，交付要件差三处

### 0.1 现在在做的事：一所学校，一间教室

我们目前在做的事：在一所学校里把 AI 教室建好，把 AI 课开出效果，向打造有口碑的 AI 教室品牌迈出第一步。（总结／目标性陈述；不用「其实就一件」这类口语化破题腔）

| 事项 | 我们的做法 |
|---|---|
| **合作对象** | 跟××合作，教室建在他们学校 |
| **硬件** | 配了数十台电脑，没有教具和课堂采集设备 |
| **课程** | 课程是我们自己配的，一课一个项目实战，不按教材章节往下走 |
| **上课工具** | 上课用豆包、即梦、LibTV 这些公开的互联网 AI 工具 |
| **下一步** | 把这间教室当成标杆慢慢做扎实…… |

### 0.2 对照标尺：调研归纳的三组框架

| 对照内容 | 所用框架 | 出处 |
|---|---|---|
| 教室怎么建 | 建设形态五类 | 2.1 |
| 怎么跟学校合作 | 合作模式六类 | 2.2 |
| 课怎么上、交付含哪些件 | 上课两条路线；交付五件套 | 2.3、第二部分开篇 |

### 0.3 对照结果：两处对得上，一处有差距

**建设形态：最轻的一档**

AI 教室怎么落地，我们这次归成五类。最轻的一档是 **SaaS 云平台型**〔术语〕：一个网页端账号加上课程资源，机房用浏览器就能开课。

- **代表厂商**：人教数字、帕拉卡、网易有道，用的都是自研平台。
- **我们的做法**：一间配了电脑的机房，用公开的互联网 AI 工具上课，投入量级跟这一档很接近。差别就一处——他们用自研平台，我们用公开工具。
- **上课方式**：走 2.3 两条路线里的「机房动手做项目」，盛思、中望、蘑菇云都走这一路。（依据 2.1、2.3）

**合作路径：单校样板校**〔术语〕

厂商和学校怎么合作，我们这次归成六类，我们走的是其中一类——**单校样板校**：先集中做好一所学校，把 AI 课真正开起来，课程怎么排、设备怎么用、课时怎么安排，都在这一所里跑通。

- **为什么叫「样板」**：这所学校是给别的学校看的样本——课上得怎么样、学生出什么作品，别人来看一眼就清楚，比拿方案去讲管用；跑通之后再照这个样复制到下一所。
- **同类做法**：帕拉卡（AI 样板校）、希沃（19 个示范区）、中望（人大附小、北京小学）都在其中，是调研中出现最多的一类。
- **行业路径**：这一类厂商走的是一条从下往上放大的路……我们也是从单校起步，跟这条路对得上。（依据 2.2）

**交付要件：五件套里占两件**

| 五件套 | 厂商的通行做法 | 我们的做法 | 结论 |
|---|---|---|---|
| **课程** | K12 三段式完整课程…… | 有配套课程，按项目实战组织，还没按 2025 版指南逐条对标 | 已经做到 |
| **平台与工具** | 自研平台或工具链…… | 豆包、即梦、LibTV 等公开互联网软件 | 已经做到（工具不是自研的） |
| **师资培训** | 多数写进交付…… | 还没有 | 还没做 |

**小结**

- **对得上的**：……（一条一件事）
- **有差别的**：……
- **站得住的**：……
- **要补的**：……（差距落在哪几项交付要件）
```

九条纪律：① **说明性文字一条不进正文**（本栏最高频问题）——栏目定位说明、口径括注与免责声明、状态注解、方法论自述、表格导语与收尾，全部删掉；口径归属写到报告头部「文档说明」一句（「……该栏为我方内部口径」），正文不再重复；**审阅免责语（「未经第三方核验」「建议向厂商索取书面确认」这类）连头部口径说明也不写**，口径说明只留标签定义（见主 skill 五）。判断标准：删掉这句，读者还能不能看懂，能看懂就删；② 现状用「事项 / 我们的做法」两列表拆开写全，总述句写**总结／目标性陈述**（在做什么事、朝哪个目标走），总述后**直接接表**，表后不加注解，不用「其实就一件」「说白了」这类口语化破题腔；③ 0.2 先立标尺（「对照内容 / 所用框架 / 出处」三列表），对照只用报告已有框架并**指回小节号**，不另造维度，表前表后不写说明句；④ 结论列只用三档白话取值——「已经做到」（可带括注）/「还没做」（「我们的做法」列写「还没有」）/「这次没涉及」，不写优劣评判与行动项（行动项归第五部分）；⑤ 语言写完整书面句、**表格行值写白话完整句**（不写「配置电脑数十台；不含教具与课堂采集设备」这类分号并列的规格书句），条目标题直接写「维度名：结论短语」（如「建设形态：最轻的一档」「合作路径：单校样板校」），**不加「其一／其二／其三」序号，收束段用「小结」**；禁「归结起来是一句话」「只回答一个问题」「合起来看」「下面逐条比对」「具体是这几项」「逐件对照如下」「其实就一件」这类模板脚手架、自我解说与口语化破题腔，也不设口径说明框（`define-box`）；⑥ **每块必须有骨架**——一块 = 一句定位句 ＋ 2–4 条要点列表（`- `），要点按「维度标签：内容」起句，`（依据 2.x）` 挂该块最后一条；小结不写整段，分四条要点（标签三字对仗：对得上的／有差别的／站得住的／要补的），一条一件事。整段流水句一律拆开；⑦ **叙述主体是人（我们），不是文档、也不是「本次调研」这个活动**——不写「报告把……归成五类」「报告里称……」「2.x 的结论是……」，也不拿「本次调研」当主语，改为「……，我们这次归成五类」「调研里叫……」「这一类厂商走的是……」；⑧ **汇报者语体（本栏专用）**——自称统一用「我们」，**整栏不出现「我方」**（合同／公文语）；列头用「事项 / 我们的做法」＋0.2 表「对照内容 / 所用框架 / 出处」＋0.3 结论列「结论」，不用「要素 / 我方现状 / 用哪组框架 / 对照结论」这类表结构语；条目标签「我方的情况」写「我们的做法」；⑨ **术语给白话定义、我方现状不用观察动词**——块标题里带行业说法的，定位句要把它拆开讲清（是什么＋为什么叫这个名），**不能只给同义改写**，并在该词后标 `〔术语〕`（**可选项：默认不加，用户明确要求才标**——2026-09-14 本报告加后撤下），让读者一眼看出这里给了白话解释；写我方现状只写「我们做了什么／还没做什么」，不写「没看到／未见某种材料」这类审阅动作。其余正文仍按第 10 节用「本次调研」作主语。完整口径见 `cyx-research-report` 八.1。

## 二、层级与标记：Markdown 怎么写

### 1. 标题层级（五层，不多不少）

| 层级 | 写法 | 示例 |
|---|---|---|
| 报告标题 | `#` 一个，全文唯一 | `# AI 教育厂商调研总结报告` |
| 部分 | `## 第N部分　标题`——**中文数字 + 全角空格**，视角用括号补 | `## 第二部分　AI 教室建设与合作模式（全公司视角）` |
| 小节 | `### N.M 小节名` | `### 2.1 AI 教室是怎么建起来的` |
| 对象详情 | `#### 对象 · 详情`——同一模板，不混用「关于 xx」「xx 简介」 | `#### 编程猫 · 厂商详情` |
| 详情内分组 | `**（a）分组名**`——字母序号，用于能力 / 平台 / 案例这类大块 | `**（a）定位与独有资产**` |

组小结用 `**总结**`（无编号，居中不加粗行）或 `### N.M 要点小结`，各组体例统一——有的组有、有的组没有，读者会以为漏了。

### 2. 表格：先表后详情

每组的固定节奏是 **速览表 → 逐家详情 → 组小结**。读者扫表拿到全貌，需要细节再下钻。

- **表头固定**，同类表全篇同构（厂商盘点固定四维：`与学校合作 | AI 产品/项目 | 运营模式 | 状态`），便于横向比对。
- **档位写进表名**：`| 档位 | 厂商 | 研判 |`，档位单元格用 `**A 类 · 第一梯队（7 家）**`——**类别名 + 中点 + 行业口径名 + 家数**。
- 表内短、详情长。表里放「谁、什么状态」，机制与数字放详情。

### 3. 加粗只用在四处

| 用途 | 示例 |
|---|---|
| 档位名 / 状态 | `**重点**`、`**B 类 · 教具/平台型（2 家）**`、`**场景错位**` |
| 要点小标题（行首） | `- **帕拉卡**：K12 六模块课程，一站式交付。` |
| 口径标签 | `（**访谈确认**口径）`、`（**厂商自述**口径）` |
| 关键限定 | 「产品成熟、案例硬，但面向**高校**教务」 |

不要用加粗当标题（`**帕拉卡详情**` 这类要立成 `####`），也不要成段加粗——加粗一多就等于没有加粗。

### 4. 引用块（`>`）只用于三处

1. **文档信息块**（报告开头）：整理时间 / 数据来源 / 分组说明 / 覆盖厂商 / 文档说明 / 口径说明，**一行一条**，不合并成段。
2. **部分导语**：一行说清范围与内容（见「一」）。
3. **局部范围提示**：如 `> 本次范围外：若要评估「教育管理 / 学情分析」方向，唯一现成选项是……`。

### 5. 列表与分隔

- **只用两级**。第三级说明这段该拆成小节或改用表格。
- **并列对象合并成条**：结论相同的多家合成一条——「明确无方案：新东方、学而思、鸿合、Makeblock、作业帮」；只有主推对象才逐家单列。
- **`---` 只分隔大结构**（部分与部分之间），不滥用。
- **文末一行斜体收口**：`*注：本总结基于……；标「未披露」项为原始资料未提供，待厂商补充。*`

### 6. 不放图标，以文字为主

**md 正文里不出现 emoji / 图标字**（📦 🧠 🔗 ✅ 🚫 🎓 🗣 🎬 ⚠️ 📄 ✍️ 🎖 这类一律不用）。理由：md 是内容基准与来源文件，
图标在不同渲染器、打印稿、diff 里显示不一致，且会挤占正文信噪比。

| 原本靠图标承担的 | 改成 |
|---|---|
| 栏目标签 | 裸文字标签：`**说课**`、`**口播**`、`**操作**`、`**提醒**`、`**交什么**`、`**过关标准**` |
| 链条与指向 | 标点 `→`（**`→` 是标点不是图标，要保留**）：`起头 → 卡住 → 出手 → 结果` |
| 并列 | `＋`；同位 `·`；分隔 `｜` |
| 页脚 | `> **0.7**　｜　第 7 页 / 共 48 页`（不写 `📄`） |

**范围**：只管 md。HTML 课件 / 学案 / 幻灯另有一套口径，图标照留（投影与打印场景需要）。

**批量去图标时的操作纪律**（血泪教训，务必遵守）：

1. **先备份**再动手。
2. **只删图标本身 ＋ 它紧邻的那一个空格**，**不要**做「先删图标、再全局压缩空格」的两步法——
   后者会把 `**说课**`、`- **口播**　正文` 这类正常间距一起吃掉，也会把 `① 起头 → ② 卡住` 的箭头压没。
   按位置区分：图标前是半角空格就连空格删；在行首或前是全角空格就吃掉它后面的一个半角空格；其余空白一律不碰。
3. **验收要逐字比对**：把新旧文件都去掉图标与全部空白后比对，必须完全相同。
   **只看「图标数 = 0」是不够的**——那只能证明图标没了，证明不了排版没被毁。
4. **改完查三类残留信号**：连续空格、行首空格、`** ` 后接空格。还应复核「靠图标当分隔符」的位置是否丢了 `→`。

## 三、语言规范

| 项 | 要求 | 反例 → 正例 |
|---|---|---|
| **人称** | 站调研视角，主语是「本次调研 / 公开资料 / 企业公开披露」 | ~~本轮核查显示~~ → 调研显示 |
| **禁用代词** | 「我们 / 笔者 / 我认为」一律不用 | ~~我们认为~~ → 从公开材料看 |
| **命名用行业口径** | 研判、第一梯队、方向不符、待回访、场景错位、候选 | ~~可落地性判断~~ → 研判 |
| **术语附白话** | 首次出现用一句人话解释，括号内给出 | 「（该平台是学习平台，不是课堂行为分析系统）」 |
| **句式** | 一句一个信息点；判语独立成句，不埋在长句中间 | 见 `cyx-research-report` 八.19 |
| **责任主体** | 每个结论点出具体厂商，不写「有的厂商」 | ~~部分厂商已有方案~~ → 帕拉卡、人教已有完整课程 |
| **不做商务判断** | 不写「值得投入 / 不必对接 / 建议合作」；匹配与否用事实说明，行动项只进第五部分 | ~~建议优先对接~~ → 6 家课程与产品体系完整 |
| **禁用空话** | 赋能、抓手、闭环、颗粒度、组合拳 | 换成具体动作与结果 |
| **数字** | 精确到档位并带单位与时间 | 「9800 元/年/学段」「19 个示范区、5600+~1.2 万所学校」 |
| **结论必有证据** | 每条结论句写清主体 + 数字 / 时间 / 资料名，能回查 | ~~多数厂商已布局~~ → 24 家中 15 家有实质业务（访谈口径） |
| **先事实后判断** | 先给可核查事实（案例 / 数据 / 方案名），再给判断；判断不越出事实范围 | ~~该产品性能领先~~ → 支持 70 亿参数本地部署（公开资料） |
| **宁缺毋造** | 查不到就不写，不用「据悉 / 预计 / 有望 / 大概」填空；确需保留标「推演 / 估算（非普查）」并列锚点 | ~~市场空间广阔~~ → 不预测，无预测来源，缺口列入待补 |
| **无假大空** | 禁无对象无度量的空话、无依据的排名与趋势；换成对象 + 量级 + 来源 | ~~赋能教育行业~~ → 覆盖 19 个示范区、5600+ 所学校（公开资料） |
| **通俗且专业（总纲）** | 说人话 + 判断有据，两者不可偏废：术语给白话定义、不拿同义词当解释；同时不因通俗而含糊，判断仍要带主体与依据 | ~~先做试点再复制~~ → 先在一所学校做样板，做出可复制的做法，再推到其他学校 |
| **段落衔接流畅** | 段与段有显性承接（因此／相比之下／进一步看），不把要点堆成互不相干的条目；读者不需要回头找主语 | ~~（三段并列，无人称承接）~~ → 每段首句承接上一段落点 |
| **禁 AI 过渡填充** | 「首先／其次／最后」三段套、「综上所述」「值得注意的是」「不难看出」、「不仅……而且……」对称排比充字数 | 直接陈述；段间必要处用一个承接词即可 |

**以上五条（通俗易懂 / 专业严谨 / 叙事逻辑闭环 / 段落衔接流畅 / 去 AI 味）是 Lulu 2026-09-21 定的跨格式语言总纲**，
适用于一切文字产出（文档、网页、表格、PPT、邮件、聊天回复、口播稿），不限于 Markdown 报告；
本表是它在报告场景下的落地形式。详见 `~/.workbuddy/MEMORY.md`「语言总纲」。

**去口语、去模板腔的完整禁用清单**见 `cyx-html-style` 第一节（两处同一份清单，不重复维护）。

## 四、逻辑与口径

### 1. 分档三件套：结论 → 速览表 → 逐档依据

分类结论不是直接列表，而是三步递进：

1. **结论**：先给数量——「已取得有效信息的 22 家厂商按匹配度分五档：第一梯队 7 家、教具/平台型 2 家、方向不符 8 家、待回访 4 家、场景错位 1 家」，并交待**没进档的为什么没进**。
2. **速览表**：档位 / 厂商 / 一句话研判。
3. **逐档依据**：每档**先一句总述，再列对象**；每条依据落到厂商，且与原表顺序一致。

**两套分档并存必须显式区分**：若同时有「按匹配度分档」与「按处理进度分档」，第二套导语里点明**角度不同**，且档位名不重名：

> 24 家厂商按**处理进度**分四档（与核心结论的「匹配度」分档角度不同）。

### 2. 口径三级标注

规模、报价这类数字按来源分级标注，全文统一：

| 标签 | 含义 |
|---|---|
| **访谈确认** | 厂商在沟通中当面/电话确认 |
| **厂商自述** | 厂商宣传或方案材料口径，未经第三方核验 |
| **公开资料** | 第三方来源（评测、政府采购公告、媒体报道） |
| **未标注** | 取自访谈记录或厂商随附文件 |

配套写法：
- **自述必带「厂商自述」标签**：「（**厂商自述**口径）」——标签本身已交代口径归属，就此打住；「未经第三方核验」这类审阅提示不写（见主 skill 五）。
- **同一指标多套口径并列**：「19 个示范区、5600+~1.2 万所学校（**公开资料**中存在两套口径且差异较大，引用须标注时间）」。
- **缺口显式列出**：「未提供报价 4 家：希沃、编程猫、科大讯飞、商汤」——缺口不写，读者会以为已齐。

### 3. 论证：事实 → 因果 → 判断，不加标签

每个判断由「可核查事实 → 推断过程 → 结论」构成，**三步在自然段落顺序中出现，不加「前提 / 推断 / 结论」标签**（标签是教读者怎么读，见 `cyx-html-style` 第 1 节）。

**结论必有案例证据**——结论性内容（判断、定性、排名、趋势）不是表达观点，而是**对已核查事实的概括**：

- **能回查**：结论句必须带主体 + 数字 / 时间 / 资料名。写不出这三样的（「不少厂商」「业内普遍」「行业领先」）就不合格。
- **先事实后判断**：先给可核查事实（案例、数据、方案名、公开动作），再给判断；判断不越出事实范围。
- **同一主体三处同名同口径**：厂商详情、分档依据、速览表里的主体名与口径必须一致。
- **无假大空**：删掉「赋能 / 大幅提升 / 前景广阔」这类既无对象也无度量的句子；无依据的排名与趋势（「行业第一」「未来三年将爆发」）要么补上比较维度与来源，要么不写。

### 4. 宁缺毋造：不知道就不写，空白优于错误

- **回查不到事实的结论整句删掉**——不要改写成更模糊的表述保留下来，模糊保留等于把印象伪装成结论。
- 不用推测性表述填空：「据悉 / 预计 / 有望 / 大概是」在没有来源时一律禁用。
- 没建立联系的，如实写「本次尚未建立联系，不计入以上分档」，**不臆造**；报价未披露就写「未披露」，不估算。
- 确需保留的推演项，标注「推演 / 估算 / 抽样（非普查）」并写出推导锚点（原始基数、折算系数、来源）。
- 缺口逐个显式列出（如「未提供报价 4 家：××、××」）——缺口不写，读者会以为已齐。
- 引用范围要收窄：「若为纯教具或职教场景可另议」——把例外的适用条件写出来。

### 5. 交叉引用与对照解释

- **交叉引用**：`详见 3.7`、`见第二部分`、`（详见 2.4 收费表）`——同一结论只写一处，别处指路。
- **新术语用对照块**：出现读者可能不熟的术语时，用 `**对照：×× 是什么**` 加四问——**采什么 / 出什么 / 做什么用 / 谁在做**，并明确标注这是支撑性说明，放在主体之后。

### 6. 叙事链闭合：全篇一条链

- **四环无断点**：结论 → 依据 → 来源 → 可信级。任一环缺掉，结论就悬空。
- **章节承接显性**：用「因此 / 相比之下 / 进一步看」过渡，不出现上一节讲 A、下一节忽然讲 C 的断裂。
- **矛盾显式处理**：相邻结论若冲突，当场说明原因（口径不同 / 时间不同 / 样本不同），不靠读者脑补。

## 五、交付前自查清单

- [ ] **五段齐全**：结论 → 规律 → 明细 → 佐证 → 行动，顺序未乱
- [ ] **先总后分**：每部分先给数量化结论，再展开依据；没有把几十条平铺列表直接摆上来
- [ ] **无同题重复**：结论区（结论＋依据＋完成度）与规律区不重写同一张表 / 同一组要点
- [ ] **导语只有一行**：部分导语用 `>` 引用块说范围与内容，无「本部分将……」式元描述
- [ ] **标题层级正确**：`## 第N部分　`（中文数字 + 全角空格）/ `### N.M` / `#### 对象 · 详情` / `**（a）分组名**`，五层不越级
- [ ] **表格先行**：每组都是「速览表 → 逐家详情 → 组小结」，同类表头全篇同构
- [ ] **加粗未滥用**：只用于档位名、要点小标题、口径标签、关键限定；无加粗冒充标题
- [ ] **引用块只在三处**：文档信息块 / 部分导语 / 局部范围提示；信息块一行一条
- [ ] **列表只两级**：并列多家已合并成条，无一家一条撑行数
- [ ] **无图标**：正文、栏目名、页脚都不含 emoji / 图标字；链条用 `→`、并列用 `＋`、分隔用 `｜`（`→` 保留）
- [ ] **人称与命名**：全文「本次调研」，无「本轮 / 我们」（**第零部分除外**——那一栏是我们自己的现状归纳，按要求用「我们」的汇报者语体，见「一」）；档位名用行业口径，无「赋能 / 抓手」
- [ ] **每结论点到厂商**：无「有的厂商 / 部分企业」这类无主体表述
- [ ] **无商务判断**：正文不出现「建议投入 / 不必对接」；行动项只在第五部分
- [ ] **前置现状对照栏（如有）**：编号独立于正文 `1`–`N`；现状用「事项 / 我们的做法」两列表写全，正文无说明性文字（口径归属在头部「文档说明」）；对照只用报告已有框架并指回小节号；结论列只用三档白话取值「已经做到 / 还没做 / 这次没涉及」；**自称用「我们」不用「我方」，主语是人（不是「报告」也不是「本次调研」）**；行业术语给了白话定义（不拿同义改写当解释）并标了 `〔术语〕`，我方现状不写「没看到／未见某种材料」这类观察动词；无优劣评判与行动项（详见「一」与 `cyx-research-report` 八.1）
- [ ] **分档三件套**：结论家数 → 速览表 → 逐档依据；两套分档角度已点明、档位名不重名
- [ ] **口径标注齐全**：规模与报价带 `访谈确认 / 厂商自述 / 公开资料` 标签，正文与口径说明区无审阅免责语
- [ ] **缺口显式**：未报价、未访谈、未建立联系的对象都写明，不臆造不估算
- [ ] **术语有解释**：不常见术语首次出现附一句白话，或用「对照：×× 是什么」四问块（标识 `〔术语〕`／`.tag.term` 为可选项，默认不加）
- [ ] **段落有骨架**：每段一个主题，判语在段首或段尾；同层段落结构对称（详见 `cyx-research-report` 八.19）
- [ ] **结论有案例证据**：每条结论句能回查到主体 + 数字 / 时间 / 资料名；无「不少厂商 / 业内普遍 / 行业领先」类无主体断言，无「赋能 / 大幅提升 / 前景广阔」类无对象无度量的空话；回查不到事实的结论已删除而非改模糊（详见 `cyx-research-report` 八.20）
- [ ] **事实优先、宁缺毋造**：每个判断都能指到上文出现的事实；查不到出处的未写、未用「据悉 / 预计 / 有望」填充；推演项已标「非普查」并列推导锚点；缺口逐个显式列出
- [ ] **叙事链闭合**：结论 → 依据 → 来源 → 可信级四环无断点；章节间有显性承接，无突然换题；相邻矛盾结论已说明原因
- [ ] **通俗且专业**：术语首次出现有人话解释（不拿同义词当解释）；通俗没换成含糊，判断仍带主体 + 依据
- [ ] **段落衔接流畅**：段间有显性承接词，不是条目堆叠；抽读各段首句能连成一条顺提纲
- [ ] **无 AI 过渡填充**：无「首先／其次／最后」三段套、「综上所述」「值得注意的是」「不难看出」、「不仅……而且……」对称排比
- [ ] **文末收口**：一行斜体注明数据口径与待补项

## 六、自我进化机制（本 skill 同步更新规则）

> **上游通用条款**：判定、留痕、回退的共性规则见 `cyx-skill-evolution`；本节与本技能包内 `cyx-research-report`「十六」同源，
> 冲突时以本技能包为准（有专属账本 `../references/feedback-log.md` 与机检 `../scripts/check-template.py`）。

**本 skill 不是一次写死的。** 用户拿本 skill 写报告时提的每一条意见，都可能是一条适用于**所有后续 Markdown 报告**的内容侧规则；把它挑出来写回本文件，本 skill 才会越用越准。本节与 `cyx-research-report`「十六」、`cyx-html-style`「七」同构，三者共用一本账（`../references/feedback-log.md`）与一次校验（`../scripts/check-template.py`）。

### 6.1 触发时机

- 用户对**内容侧**提意见：结构、层级、标记、表格、措辞、命名、视角、口径、术语、分点与分层。
- **同一类意见在同一会话里反复出现（≥2 次）**——最强信号：不是当期报告的问题，而是本 skill 的**默认写法错了**，必须从「建议」升级为「强约束」（加粗、进自查清单、加机检）。

### 6.2 内容侧反馈 → 本 skill 落点

| 反馈类型 | 典型原话 | 改本文件哪一节 |
|---|---|---|
| 结构骨架 | 「太散了，先总结再分」「不要大段黏在一起」「分清主次」 | 一（五段骨架表 + 四条骨架纪律） |
| 层级与标记 | 「加粗太多」「标题层级乱」「表格顺序不对」「引用块滥用」 | 二.1 标题层级 / 二.2 表格 / 二.3 加粗 / 二.4 引用块 / 二.5 列表 |
| 措辞与命名 | 「换个总结性的词」「用行业口径命名」「不要弱化字眼」「不要判断式收尾」「不要商务判断」 | 三（语言规范表） |
| 视角与元信息 | 「用本次调研视角」「不要出现本轮」「删前置性说明」「删修订说明」 | 一（导语只写一行）+ 三（人称 / 禁用代词） |
| 逻辑与口径 | 「结论要有事实依据」「要点出是哪家公司」「口径要标清」 | 四.1 分档三件套 / 四.2 口径三级标注 / 四.3 论证 |
| 术语可读性 | 「这个词解释清楚些」「看不懂」 | 三（术语附白话）+ 四.5（对照块四问） |
| 内容增删 | 「这段不要了」「补一个维度」 | 一（骨架表增删行）+ 五（自查清单同步） |

**推演要点**：改动落在哪一节，就要在**同节的表里**就地改（第 3 行「措辞」→ 改三的表行本身，不新起一节讲措辞），并同步「五、交付前自查清单」——只改前面、不改清单，下次交付仍会漏。

### 6.3 越界处理：不属于内容侧的反馈转出去

| 反馈其实落在 | 转给 | 对方落点 |
|---|---|---|
| 配色 / 字号 / 版心留白 / 组件样式 / 观感「像 AI 生成」 | `cyx-html-style` | 其「七.2 视觉侧反馈 → 本 skill 落点」表 |
| 数据来源可信度 / 脚注 / 论证链红线 / 多格式交付链路 | `cyx-research-report` | 其「十六.4 / 十六.5」 |
| 只对这一份报告成立的结论或数字 | — | 不改 skill，只改当期产物 |

### 6.4 落盘纪律（三不写）

1. **不与已有条目重复**：同类已在 → 就地强化表述并把该条升为强约束，不新起一节。
2. **不写死具体数值与个案结论**：用户说「这个词换掉」，写「措辞用行业口径、不用判断式收尾」（可复用），不写「某家厂商属于第一梯队」（只对当期报告成立）。
3. **写不成判据或清单项的模糊直觉不进文件**：要么能落成表格里的一行对照，要么能落成自查清单的一项，否则只改当期产物。

### 6.5 留痕与校验

1. 在 `../references/feedback-log.md` 追加一行：`日期 / 原话节选 / 类别 / 归属 skill / 落点 / 处置`，「归属 skill」填 `cyx-md-style`。
2. 同类 ≥2 次 → 在本文件对应条目加粗升为强约束，并在「五、交付前自查清单」加一项。
3. 跑 `../scripts/check-template.py`（第 9 组校验三个 skill 的进化条款是否齐全），全过才算沉淀完成。
4. 一句话告知用户：「这条我记进 cyx-md-style 了，以后默认这样做。」
